# Bustation: Idle Bus

Situs: [bustation.games](https://bustation.games)

Game idle tycoon terminal bus tipe C. Penumpang melewati **Peron → Loket → Keberangkatan**. Pendapatan ditentukan oleh tahap paling lambat (bottleneck) dan banyaknya penumpang yang datang (kepuasan & jam). Terminal berjalan sendiri sejak awal: upgrade tahap, jaga kepuasan supaya penumpang makin ramai, dan rekrut Kepala supaya tetap dapat penghasilan saat app ditutup.

Stack: TypeScript + Vite · three.js + postprocessing (adegan 3D) · Capacitor 7 (Android) · break_infinity.js · Vitest.

## Menjalankan di browser

Butuh Node `^20.19` atau `>=22.12`.

```bash
npm install
npm run dev         # buka URL yang muncul; pakai mode HP di DevTools (mis. 390×844)
npm run test        # unit test
npm run build       # typecheck strict + build ke dist/
```

Save tamu disimpan di `localStorage` (kunci `terminal-bus-tycoon/save`; awalan nama lama game sengaja dipertahankan supaya progres pemain tidak hilang). Untuk mulai ulang, hapus kunci itu lewat DevTools → Application → Local Storage.

**Akun & cloud save (web):** pemain bisa masuk dengan Google (tombol akun di pojok adegan). Save lokal tetap dipakai, dan salinannya disinkronkan ke Firestore proyek Firebase `bustation-a4de9` (`saves/{uid}`), paling sering tiap 60 detik dan saat app ke background. Saat login, save tamu dipindah ke akun; logout = mulai sebagai tamu baru. Kalau dua save sama-sama berprogres dan berbeda, pemain selalu ditanya. Kode: `src/app/akun.ts` (logika, dites), `src/platform/firebase.ts`, `src/ui/popup-akun.ts`, `src/ui/popup-pilih-save.ts`. Security rules ada di `firestore.rules`; setelah diubah, tempel ulang di Firebase console → Firestore → Rules. Di APK tombol akun belum tampil (login Google di APK butuh plugin native).

## Rilis web (PWA) & pembaruan in-game

Versi web adalah PWA (`vite-plugin-pwa`): bisa dipasang ke layar utama ("Install app" / "Tambahkan ke layar utama") dan dimainkan offline. Situs resmi `bustation.games` di-host di Cloudflare Pages (project `bustation`): deploy dengan `npm run deploy:web` (build lalu `wrangler pages deploy`; sekali saja jalankan `npx wrangler login` dulu). Deploy harus lewat Wrangler dari folder ini, bukan unggah lewat dashboard, supaya `functions/` dan `wrangler.toml` ikut:

- `functions/__/[[path]].js` meneruskan `/__/*` ke `bustation-a4de9.firebaseapp.com` sehingga login Google berjalan di domain sendiri (juga di Safari/iPhone);
- `functions/api/peringkat/` adalah API papan peringkat. Binding database D1-nya (`DB` → `bustation-peringkat`) ada di `wrangler.toml`.

Karena `wrangler.toml` ada, pengaturan binding Pages dikelola di file itu, bukan di dashboard. Path aset relatif (`base: './'`). HTTPS wajib (kecuali `localhost`).

**Merilis versi baru:**

1. Naikkan `version` di `package.json` (mis. `0.1.0` → `0.2.0`).
2. Isi `catatan` di `src/config/rilis.config.ts` (±4 butir "Yang baru", tampil di popup).
3. Kalau versi lama tidak boleh dipakai lagi (mis. format save berubah), naikkan `versiMinimal` di file yang sama. Pemain di bawah versi itu mendapat popup wajib tanpa tombol "Nanti".
4. `npm run deploy:web`.

**Yang dilihat pemain:** service worker mengunduh rilis baru di latar. Game memeriksanya saat dibuka, tiap 30 menit selama terbuka, dan setiap kali tab/app kembali terlihat. Setelah rilis baru siap, muncul popup **"Versi baru tersedia"** berisi `0.1.0 → 0.2.0` dan catatan dari `versi.json` rilis baru, dengan tombol **Perbarui sekarang** (progres disimpan dulu, lalu game dimuat ulang ke versi baru) dan **Nanti**. Setelah "Nanti", tombol hijau berpanah dengan titik merah muncul di pojok adegan untuk memperbarui kapan saja. Popup ini menunggu popup lain (mis. "Selama kamu pergi…") ditutup dulu. Kode: `src/app/pembaruan.ts` (logika versi, dites), `src/platform/pembaruan.ts` (service worker), `src/ui/popup-pembaruan.ts`.

**Catatan hosting:** `sw.js` dan `versi.json` jangan di-cache lama oleh server/CDN (bawaan hosting statis umumnya sudah aman). `versi.json` sengaja tidak masuk precache service worker.

**Mencoba alur pembaruan di komputer:** `npm run build && npm run preview`, buka di Chrome, lalu naikkan versi, build lagi, dan kembali ke tab game (atau tunggu pemeriksaan berkala). Di `npm run dev` dan di APK, service worker tidak aktif. Di APK, kode game ikut di dalam APK, jadi pembaruan APK nanti lewat Play Store/unduhan APK baru.

**Ikon aplikasi** (`public/ikon*.png`, `ikon.svg`, `apple-touch-icon.png`) dibuat dari gambar vektor di `tools/ikon/buat-ikon.mjs`: ubah gambarnya lalu jalankan `npm run ikon` (butuh Chrome).

**Pratinjau link** (WhatsApp, Facebook, X): `public/og-image.jpg` 1200×630 (±200 KB; WhatsApp sering tidak menampilkan pratinjau di atas ±300 KB), dipasang lewat meta `og:image` & `twitter:card` di `index.html`. Gambar dibuat dari adegan game dengan `shot.mjs` (UI disembunyikan, judul ditempel); `.jpg` tidak ikut precache PWA. Setelah deploy, cache pratinjau lama di Facebook/WhatsApp bisa disegarkan lewat [Sharing Debugger](https://developers.facebook.com/tools/debug/).

**Kebijakan privasi**: `public/privasi.html` (di situs: `https://bustation.games/privasi`), bahasa Indonesia + versi Inggris, mengacu ke UU No. 27/2022 (PDP). Ditautkan dari menu Akun ("Dengan masuk, kamu menyetujui Kebijakan Privasi") dan lewat `<link rel="privacy-policy">` di `index.html`; `/privasi` dikecualikan dari navigateFallback PWA supaya tidak dijawab halaman game. Isinya harus diperbarui (kedua bahasa, termasuk tanggal berlaku) setiap kali pemrosesan data berubah. Sejak 1 Oktober 2026 kebijakan itu sudah mencakup papan peringkat (bagian 2g) dan iklan berhadiah Google AdSense (bagian 2f: cookie iklan, cara menolak iklan yang dipersonalisasi, persetujuan di Eropa). Kalau penyedia iklan bertambah (AdMob di APK, portal game), perbarui bagian itu lebih dulu. Tautan ini juga dipakai untuk Play Store & portal game.

## Papan peringkat (server)

API kecil di Cloudflare Pages Functions dengan database **Cloudflare D1** `bustation-peringkat` (region APAC, skema di `migrations/`):

| Rute | Siapa | Isi |
|---|---|---|
| `GET /api/peringkat?minggu=YYYY-MM-DD` | publik | 50 teratas minggu ini (atau minggu lalu) + jumlah peserta, di-cache di edge 60 dtk |
| `GET /api/peringkat/saya` | login | skor & peringkat sendiri (dihitung sampai 1.000) |
| `POST /api/peringkat` | login | kirim skor `{minggu, skor, kelas, nama}` |
| `DELETE /api/peringkat` | login | hapus semua skor sendiri (keluar papan / hapus akun) |

- **Login** = header `Authorization: Bearer <ID token Firebase>`. Server memverifikasi token sendiri (`server/token-firebase.ts`): tanda tangan RS256 dengan kunci publik Google yang di-cache, `aud`/`iss` proyek `bustation-a4de9`, kedaluwarsa, dan hanya login Google. Tanpa SDK Admin dan tanpa kunci rahasia di repo.
- **Validasi kiriman** (`validasiKiriman` di `src/app/peringkat.ts`, `server/peringkat.ts`):
  - minggu harus minggu ini menurut jam server (minggu lalu masih diterima 10 menit setelah Senin 00.00);
  - nama dirapikan & disaring;
  - satu kiriman per akun tiap 20 detik;
  - skor tidak pernah turun, dan tidak boleh naik melebihi arus 100.000 pnp/dtk × 3× kecepatan sejak kiriman sebelumnya;
  - akun di tabel `larangan` ditolak.
- **Kode**: `functions/api/peringkat/*.ts` (pintu masuk), `server/` (handler, verifikasi token, kueri D1), `migrations/0001_papan_peringkat.sql`. Hanya minggu ini & minggu lalu yang disimpan; yang lebih tua dibuang saat kiriman berikutnya.

**Moderasi** (perintah dari folder ini; `--remote` = database produksi):

```bash
# 10 teratas minggu ini beserta uid (uid tidak pernah tampil di game)
npx wrangler d1 execute bustation-peringkat --remote --command "SELECT uid, nama, kelas, skor FROM papan WHERE minggu = '2026-09-28' ORDER BY skor DESC LIMIT 10"
# blokir akun curang/nama tidak pantas, lalu hapus skornya
npx wrangler d1 execute bustation-peringkat --remote --command "INSERT INTO larangan (uid, alasan, dibuat) VALUES ('UID', 'skor tidak wajar', 0); DELETE FROM papan WHERE uid = 'UID'"
```

**Mencoba di komputer:** `npx wrangler d1 migrations apply bustation-peringkat --local` (sekali), `npm run build`, lalu `npx wrangler pages dev dist --compatibility-date=2026-05-03` (port 8788, D1 lokal di `.wrangler/`). Jalankan `npm run dev` di terminal lain: Vite meneruskan `/api` ke port 8788, dan login Google tetap jalan di `localhost`. `--compatibility-date` diturunkan karena wrangler lokal belum mengenal tanggal proyek (2026-09-28); di produksi tetap memakai tanggal di `wrangler.toml`.

**Mengubah skema:** tambah `migrations/0002_….sql`, coba dengan `--local`, lalu `npx wrangler d1 migrations apply bustation-peringkat --remote` **sebelum** deploy kode yang membutuhkannya.

**Kuota gratis** (cukup untuk ribuan pemain aktif):

| Layanan | Batas | Pemakaian |
|---|---|---|
| D1 baca | 5 juta baris/hari | tiap tampilan papan ±50 baris, tapi di-cache 60 dtk; peringkat sendiri ≤1.000 baris, paling sering tiap 5 menit per pemain |
| D1 tulis | 100 ribu baris/hari | ±1 kiriman per 3 menit per pemain yang ikut |
| Workers | 100 ribu permintaan/hari | semua rute `/api` |

Kalau pemain bertambah banyak, naik ke Workers Paid ($5/bulan).

## Pengelolaan terminal

Panel bawah punya enam tab: **Tahap** (peron, loket, keberangkatan), **Fasilitas** (termasuk jalur bus), **PO** (mitra PO), **Terminal** (level & kelas, perluasan, Renovasi, kelas bus), **Modern**, dan **Target**. Semua angka ada di `src/config/economy.config.ts` (ditandai PLACEHOLDER); logikanya di `src/sim/state.ts` serta modul murni `src/sim/mitra.ts`, `segmen.ts`, `level-terminal.ts`, dan `perluasan.ts` (dites di `tests/fitur.test.ts`, `armada.test.ts`, `mitra.test.ts`, `segmen.test.ts`, `kelas.test.ts`, `harga.test.ts`). Rancangan lengkapnya ada di `documents/12-rancangan-ekonomi-po.md`. Satu PO di Lv 1 dengan reputasi netral (50) dan harga normal menghasilkan tiket yang sama dengan ekonomi tiga tahap spreadsheet. Di luar jam ramai arus ikut penumpang yang datang (lihat Kepuasan penumpang).

- **Sumber uang** hanya empat, semuanya mengikuti arus penumpang (tahap paling lambat) dan pengali pendapatan (Renovasi × level terminal × event × kepuasan; `rincianPendapatan` & `pengaliPendapatan` di `src/sim/state.ts`). Uang **masuk per transaksi**, bukan sebagai aliran per detik (`tick` & `TransaksiState`): tiap penumpang utuh yang membeli tiket membayar tiket & parkir kendaraannya, tiap 20 penumpang (1 bus) membayar parkir bus, dan sewa kios dibayar harian. Pecahan penumpang/bus yang belum utuh disimpan (ikut save), jadi totalnya sama dengan arus × harga:
  - **tiket** di loket: harga tiket PO untuk jurusan & kelas busnya (lihat Mitra PO & Harga tiket), dibayar tiap penumpang;
  - **parkir bus jurusan** (`retribusi` di kode): dibayar tiap bus yang parkir di pulau jurusannya (1 bus = `penumpangPerBus` 20 penumpang), level Parkir Bus Jurusan menaikkan tarif per bus;
  - **parkir kendaraan** pengantar & penjemput: dibayar tiap penumpang;
  - **sewa kios**: belanja penumpang di Kios & Minimarket dikumpulkan sepanjang hari terminal lalu **dibayar sekaligus saat hari berganti** (tengah malam, notifikasi "Sewa kios hari …"). Saat game ditutup, belanja kios ikut dihitung dalam penghasilan offline.

  **Toilet & Musholla** tidak menghasilkan uang; tiap level menaikkan belanja di kios (+10%). HUD tidak menampilkan laju per detik, melainkan **"Hari ini Rp X · N tiket"** (hasil operasi & tiket terjual hari terminal ini, dari `rekor`). Laju per detik tetap dipakai di dalam sim untuk penghasilan offline, boost 2×, dan hadiah "N menit pendapatan" (rata-rata keempat sumber). Boost 2× ikut menggandakan belanja kios.
- **Fasilitas**: Kios & Minimarket, Parkir Kendaraan, Toilet & Musholla, Parkir Bus Jurusan. Tab Fasilitas menampilkan efek masing-masing (sewa ±Rp/hari & yang terkumpul hari ini, Rp/penumpang, % belanja kios, Rp/bus); biaya naik eksponensial seperti upgrade tahap. Di 3D, penjaga kios & toko, juru parkir, petugas kebersihan toilet, dan petugas pos retribusi baru hadir setelah fasilitasnya dibangun.
- **Jalur bus** (baris teratas tab Fasilitas; logika di bagian Jalur bus `src/sim/state.ts`, angka di `EKONOMI.jalur`): terminal baru hanya punya **1 jalur**, paling banyak 5. Jalur 2–5 dibangun berurutan (Rp 300, Rp 25 rb, Rp 1,5 jt, Rp 60 jt), dan tiap jalur tambahan menaikkan kapasitas Peron & Keberangkatan +40 % (`multJalur`). Loket tidak ikut naik, jadi setelah membangun jalur loket perlu dikejar lagi (pilihan yang disengaja). Jalur **permanen**: tidak diulang saat Renovasi. Save lama tanpa blok ini tidak menyusut: jumlah jalurnya mengikuti tonggak level (25/50/100/200) yang sudah dicapai Peron & Keberangkatan. Di adegan, terminal terlihat "tumbuh" (`src/game/pembangunan3d.ts`). Halte peron kedatangan dan gerbang keberangkatan milik jalur yang belum dibangun ditutup kerucut & palang merah-putih, dan gerbangnya juga ber-rolling door (`src/game/malam3d.ts`). Bus hanya singgah di jalur yang buka (`Barisan.aktif` di `src/game/dunia-visual.ts`), jadi dengan sedikit jalur bus mengantre di jalan raya. Penghargaan "Lima Jalur" untuk semua jalur. Notifikasi "🚧 Jalur N dibuka!".
- **Kepuasan penumpang** (pil 😐 N% di HUD yang bisa diketuk untuk rinciannya; rumus murni di `src/sim/kepuasan.ts`, angka di `EKONOMI.kepuasan`, dites di `tests/kepuasan.test.ts`): nilai turunan, tidak disimpan. Rata-rata berbobot tiga komponen:
  - **kelancaran antartahap** (40 %): kapasitas tahap paling lambat dibanding yang tercepat; 100 % bila ≥ 85 %, 0 % bila ≤ 25 %;
  - **Kios & Toilet** (30 %): level Kios + Toilet dibanding kebutuhan arus, 1 + 1,5 × log₂(1 + arus);
  - **jalur bus** (30 %): jalur dibanding kebutuhan arus, 1 + ⌊1,6 × log₁₀(1 + arus)⌋, paling banyak 5.

  Di atas **70 %** semua pendapatan naik, sampai **+25 %** di kepuasan 100 % (`pengaliKepuasan`, termasuk penghasilan offline). Di bawah 70 % tidak ada bonus. Kepuasan juga mengangkat reputasi semua PO (lihat Mitra PO).

  **Makin puas, makin banyak penumpang datang** (`permintaanPenumpang` & `keterisianTerminal` di `src/sim/state.ts`, angka di `EKONOMI.permintaan`, dites di `tests/state.test.ts`). Permintaan = daya tarik × ritme: daya tarik = 1 + 0,6 × kepuasan, ritme = 0,4 + 0,6 × keramaian jam & hari (lihat Ritme keramaian harian). Penumpang lalu dibagi ke kursi tiap PO (lihat Mitra PO). Di jam sibuk penumpang melebihi kapasitas (antre di tahap paling lambat). Malam hari terminal berangsur sepi tapi tidak pernah berhenti. HUD "Arus", tiket, retribusi, parkir, belanja kios, XP PO & terminal, progres target penumpang, event, tantangan, dan skor papan peringkat mengikuti arus nyata. Besarnya target, hadiah "N menit pendapatan", rekor arus tertinggi, dan penghasilan offline tetap dihitung dari kapasitas (jam terminal berhenti saat game ditutup). Kepuasan sendiri dihitung dari kapasitas, jadi tidak naik-turun mengikuti jam. Di adegan, bus & calon penumpang yang datang ikut daya tarik yang sama (`hitungLajuVisual` di `src/game/laju.ts`), lalu ritme jam. Popup kepuasan menampilkan tambahan penumpang berkat kepuasan dan kapasitas yang terisi sekarang.

  Popup rincian menyarankan langkah per komponen (tahap yang tertinggal, level fasilitas yang dibutuhkan, jumlah jalur). PO premium hanya mau didaftarkan & diperpanjang kontraknya bila kepuasan cukup: Telolet Jaya 65 %, Sultan Garasi 80 %.
- **Mitra PO** (tab PO; logika di bagian Mitra PO `src/sim/state.ts` & `src/sim/mitra.ts`, angka di `EKONOMI.mitra`): dua puluh perusahaan otobus fiktif dengan tingkat **Lokal / Regional / Nasional / Premium**. Tingkat menentukan kelas bus tertinggi (Lokal sampai Eksekutif, Regional sampai Sleeper, Nasional & Premium sampai Double Decker), loket bawaan (2/3/4/4), dan reputasi awal. Game baru dimulai dengan **PO Ondel-Ondel** (Jakarta) yang menyewa satu loket.
  - **Jurusan**: tiap PO melayani tiga kota; yang kedua terbuka di PO Lv 6, yang ketiga di Lv 12, dan rute antarpulau juga butuh kelas terminalnya. PO berbeda boleh melayani jurusan yang sama dan bersaing di sana.
  - **Kelas bus** terbuka seiring level PO: Patas AC Lv 3, Eksekutif Lv 6, Sleeper Lv 10 (butuh Terminal Tipe B), Double Decker Lv 15 (Tipe A), sebatas tingkat PO. Nilai tiket kelas ×1 / 1,25 / 1,6 / 2,1 / 2,6. Penghargaan "Armada Lengkap" saat kelima kelas beroperasi (dari PO mana pun yang punya loket).
  - **Loket**: tahap Loket = loket milik terminal yang disewa PO. Upgrade Loket membangun satu loket untuk PO yang paling menguntungkan per kursi (panel menyebut tujuannya, mis. "→ PO Ondel-Ondel"); di kartu PO tombol "+ Loket" memilih PO-nya. Jatah loket PO = 6 + 4 × (level − 1) + bonus perluasan. Kapasitas Loket hanya dari loket yang disewa PO. Loket kosong (PO keluar) diisi lagi gratis lewat tombol "Isi loket", atau otomatis oleh Kepala Loket.
  - **Level PO** dari XP: tiap 20 penumpang PO itu = 1 bus = 1 XP, ditambah 10 % kebutuhan level untuk tiap loket baru di atas rekor loket PO itu (loket yang dibangun ulang setelah Renovasi tidak dihitung lagi). XP kumulatif = 15 × (L − 1)³. Nilai tiket PO ×1,06 per level. XP juga bertambah saat game ditutup (efisiensi offline).
  - **Pembagian penumpang** (`src/sim/segmen.ts`, dites di `tests/segmen.test.ts`): kursi terminal dibagi ke PO sebanding loketnya, lalu ke jurusan & kelas PO itu sebanding peminatnya. Calon penumpang tiap segmen = permintaan × faktor reputasi (0,7–1,3) × (harga ÷ normal)^(−elastisitas) × persaingan antar-PO di jurusan yang sama × kejenuhan rute. Tiket = kursi terisi × nilai jurusan × nilai kelas × nilai PO × harga.
  - **Reputasi** (0–100) bergerak pelan menuju 50 × kepuasan + 30 × skor harga + 20 × banyaknya kelas ÷ 5 (konstanta waktu 20 menit main). Tiket mahal menurunkan reputasi PO-nya, bukan kepuasan terminal.
  - **Mendaftarkan PO** (tab PO, bagian "Daftarkan PO"): butuh slot kosong (level terminal), biaya daftar (Rp 50 sampai Rp 50 M), dan kelas terminal yang cukup. PO premium juga butuh kepuasan. PO hadiah gratis: Juara Kelas (Tipe B), Juara Umum (Tipe A), dan PO event setelah tahap terakhir event musiman. PO langsung menyewa loket bawaannya, dari loket kosong lebih dulu.
  - **Kontrak** 7 hari terminal (PO hadiah 14), hanya berkurang saat main. Perpanjang = 10 menit pendapatan PO itu, sisa paling lama 14 hari. Selama event semua pendapatan dikali (Mudik ×1,5, Nataru ×1,3, HUT RI ×1,17; termasuk penghasilan offline & hadiah "N menit pendapatan"), dan ada tiga tahap target "berangkatkan N penumpang" (N = arus saat event dimulai × 20 menit / 1 jam / 3 jam main) dengan hadiah 5/15/30 menit pendapatan; tahap terakhir membuka mitra PO eksklusif yang bisa didaftarkan gratis (Mudik Ceria, Merah Putih, Kembang Api). Progres & hadiah dicatat per edisi (mis. `mudikLebaran-2027`): dibuka ulang di tengah event melanjutkan progres, hadiah yang sudah tercapai tetap bisa diklaim setelah event selesai, edisi berikutnya mulai dari nol. Kosong = papan bawaan "TERMINAL TIPE C". Disimpan di blok `profil` dan tidak hilang saat Renovasi. Analitik hanya mencatat ada/tidaknya nama, **tidak pernah namanya**.

- **Tantangan mingguan** (kartu di tab Target; minggu & pilihan jenis murni di `src/sim/tantangan.ts`, logika di bagian Tantangan `src/sim/state.ts`, angka di `EKONOMI.tantangan`, dites di `tests/tantangan.test.ts`): mengikuti **jam nyata WIB**, minggu baru tiap **Senin 00.00 WIB**. ## Hadiah iklan berhadiah

Pemain **memilih sendiri** menonton iklan untuk hadiah; tidak ada iklan paksa dan tidak ada fitur gratis yang dikunci. Angkanya di `EKONOMI.hadiah` (`src/config/economy.config.ts`), logikanya di bagian Hadiah `src/sim/state.ts` (murni, dites di `tests/hadiah.test.ts`):

- **Ambil 2×** di popup "Selama kamu pergi…": penghasilan offline laporan itu diberikan sekali lagi (sekali per laporan; tidak disimpan, hanya ditawarkan di popup).
- **Boost pendapatan 2×** (tombol ⚡ di kolom kontrol, lencana sisa waktu): +30 menit waktu main per iklan, ditumpuk sampai 4 jam. Tetap berjalan (dan habis) saat game ditutup: detik offline yang ter-boost ikut 2×. HUD menampilkan pendapatan yang sudah di-boost dengan tanda ⚡2×.
- **Bus Emas**: tiap 5–10 menit waktu main (diundi dari benih game) muncul penanda "Bus Emas!" dan bus berwarna emas melintas di jalan raya. Selama 60 detik bisa diketuk: tonton iklan untuk bonus 10 menit pendapatan. Setelah diketuk, bus menunggu selama pemain menonton; "Nanti" = bus pergi dan dijadwalkan lagi.
- **Klaim 2×** target harian & penghargaan (tombol emas di tab Target).

Penyedia iklannya terpisah (`src/app/iklan.ts` kontraknya, `src/platform/iklan.ts` penyedianya), jadi bisa diganti tanpa mengubah mekanik.

**Google H5 Games Ads (web)** sudah terpasang, tapi **nonaktif** selama `ID_PENERBIT_ADSENSE` di `src/config/iklan.config.ts` kosong:

- Alurnya mengikuti Ad Placement API (`src/app/iklan-h5.ts`, dites di `tests/iklan-h5.test.ts`):
  - game meminta jeda `reward` lebih dulu. Tombol hadiah (⚡ boost, Bus Emas, klaim 2×) baru muncul setelah Google memanggil `beforeReward` (ada iklan siap);
  - ketukan pemain memanggil `showAdFn` langsung. Hadiah hanya diberikan pada `adViewed`, sedangkan `adDismissed` berarti tanpa hadiah. Suara game dibisukan selama iklan;
  - tanpa iklan (belum disetujui, stok kosong, dibatasi frekuensi, atau skrip diblokir ad blocker), tombol tetap tersembunyi dan permintaan diulang dengan jeda makin panjang (15 dtk → 5 menit).
- Sudah dicoba dengan iklan uji Google: iklan tayang, lalu boost 2× diberikan setelah iklan selesai.
- **Mengaktifkan**:
  1. Daftar Google AdSense, lalu isi ID penerbit (`ca-pub-` + 16 angka) di `iklan.config.ts` dan `npm run deploy:web`. Build otomatis memasang meta `google-adsense-account` di `index.html` dan `/ads.txt`.
  2. Tunggu situs disetujui, lalu ajukan H5 Games Ads untuk bustation.games.
  3. Di AdSense → *Privasi & pesan*, aktifkan pesan persetujuan untuk Eropa. Kebijakan privasi bagian 2f sudah menjanjikannya.
  4. Coba di `https://bustation.games/?iklan=uji` (iklan uji Google, tanpa pendapatan).
- ID boleh diisi sebelum H5 Games Ads disetujui: selama Google belum memberi iklan, tombol hadiah tidak muncul.
- APK nanti memakai AdMob lewat plugin native; di APK iklan selalu nonaktif dulu.

**Iklan contoh**: di `npm run dev` dan di situs dengan **`?iklan=contoh`** (mis. `https://bustation.games/?iklan=contoh`) muncul layar hitung mundur 5 detik (bisa dilewati tanpa hadiah) untuk mencoba mekanik hadiah tanpa jaringan iklan. Tanpa ID penerbit, pemain biasa & APK tidak melihat tombol hadiah dan Bus Emas tidak ditampilkan.

## Tutorial & analitik

- **Tutorial terpandu** untuk game yang benar-benar baru (`src/app/tutorial.ts`, murni dan dites; tampilannya `src/ui/tutorial.ts`): sambutan singkat, lalu empat langkah (terminal sudah berjalan sendiri, tanpa tombol PROSES): (1) upgrade tahap PALING LAMBAT, (2) rekrut Kepala termurah, (3) bangun Kios & Minimarket, (4) bangun Jalur 2 di tab Fasilitas (tujuan pertama yang terlihat di adegan: bus tidak lagi antre di jalan raya). Diakhiri gelembung penutup berisi tips klakson telolet. Tidak pernah menghalangi: pemain boleh melakukan apa saja, dan tiap langkah selesai sendiri begitu syaratnya terpenuhi (urutan bebas). Gelembung ada di bawah adegan dan tombol yang dituju berkedip kuning; bila tombolnya tersembunyi (tab lain terbuka atau panel diringkas), yang disorot tab/tombol buka panelnya. Kemajuan uang ditampilkan ("Uang Rp 6 / Rp 50"). "Lewati" kapan saja. Status disimpan per perangkat (`terminal-bus-tycoon/tutorial`: aktif/selesai/dilewati); save lama yang sudah berjalan tidak mendapat tutorial.
- **Analitik** (Google Analytics 4 lewat gtag.js, tanpa SDK Firebase supaya pemain tamu tidak mengunduh Firebase): ID pengukuran `G-L03D1C21GC` (proyek Firebase bustation-a4de9) di `src/config/analitik.config.ts`; kosongkan `ID_GA4` untuk mematikannya. Hanya di web (bukan APK), tanpa sinyal Google & personalisasi iklan. Peristiwa (`src/app/analitik.ts`, murni dan dites): `mulai_game` (save baru/dimuat, tamu/login), `tutorial_begin` / `tutorial_langkah` / `tutorial_complete` / `tutorial_lewati`, `upgrade_tahap` (hanya di level 2, 5, 10, 25, 50, 100, …), `rekrut_kepala`, `bangun_fasilitas` (level 1 & level tonggak), `beli_teknologi`, `daftar_po` (PO & jumlah PO terdaftar), `putus_po`, `perpanjang_po`, `po_keluar` (kontrak habis), `atur_harga` (PO & jurusan, sekali per sesi tiap pasangan), `mulai_perluasan` (tahap), `renovasi` (jumlah & poin yang didapat), `klaim_event` (edisi & tahap), `klaim_target`, `klaim_penghargaan`, `iklan_hadiah` (tempat & hasil), `hadiah_boost` / `hadiah_bus_emas` / `hadiah_offline_2x`, `login`, `telolet` (sekali per sesi), `foto_terminal`, `share` (peristiwa bawaan GA4: `method` web_share/unduh), `mode_sinema` (waktu & cuaca), `adegan_siap` (detik sampai 3D siap) / `adegan_gagal`, `buka_jalur` (jalur ke-N), `nama_terminal` (hanya `ada` true/false, bukan namanya), `klaim_tantangan` (jenis & minggu), `peringkat_buka` (`akun` tamu/login, `ikut`), `peringkat_ikut` / `peringkat_keluar` (tanpa nama terminal). Dua peristiwa fondasi untuk membaca data:
  - `exception` (peristiwa bawaan GA4): error JavaScript & promise yang tidak tertangani, plus kegagalan 3D. Isinya `description` (pesan ≤ 100 karakter + `@berkas:baris`) dan `fatal`. Tiap pesan dikirim sekali, paling banyak 10 per sesi;
  - `ringkasan_sesi`: dikirim saat game masuk background (tab ditutup/disembunyikan, aplikasi dijeda), lalu dihitung ulang saat kembali. Isinya `detik` (nyata), `detik_main`, `penumpang`, `pendapatan_log10`, `upgrade`, `kelas` & `level_terminal`, `jalur`, `jurusan` (yang dilayani PO), `po` (PO terdaftar), `level_rata`, `kepuasan` (%).

  Retensi (kembali besok / minggu depan) dihitung GA4 sendiri. Kebijakan privasi (`public/privasi.html`) menyebut ringkasan sesi & laporan error. Di `npm run dev` peristiwa hanya ditulis ke konsol (`console.debug`, level Verbose); `?analitik=debug` di situs mengirimnya ke DebugView GA4 sekaligus menulis ke konsol.

## Kehidupan terminal sehari-hari

Murni tampilan; logika jam & rute di `src/game/kehidupan-malam.ts` dan `src/game/jadwal.ts` (dites di `tests/kehidupan.test.ts`).

- **Jam buka**: minimarket di aula buka 24 jam; apotek buka 07–22, kios ruang tunggu (kopi, roti, oleh-oleh) 05–22.30. Saat tutup, rolling door seng turun dan penjaganya pulang (`src/game/malam3d.ts`). Selama fasilitas **Kios & Minimarket** belum dibangun, minimarket, apotek, dan ketiga kios ruang tunggu tertutup rolling door sepanjang hari, tanpa penjaga, dan tidak didatangi penumpang (`kiosDibangun` di `LajuVisual`). Pukul 22–05 separuh jendela loket yang buka ikut tutup, paling sedikit dua tetap buka (rolling door bertulisan TUTUP, tanpa petugas); pembeli hanya dipanggil ke jendela yang buka.
- **Malam**: pukul 19–05.30 satpam luar berkeliling plaza menyusuri pagar (siang berjaga di posnya); pukul 21–05 dua petugas kebersihan berseragam menyapu lantai aula dan ruang tunggu dengan sapu ijuk.
- **Luar pagar** (`src/game/luar3d.ts`): pangkalan ojek di mulut gang gerbang KELUAR (gubuk beratap dengan bangku & papan "PANGKALAN OJEK", tiga ojek menunggu penumpang turun; di atas pukul 23 tinggal satu), pengemudi ojol berjaket hijau di mulut gang gerbang MASUK (jumlahnya ikut keramaian), dan dua pedagang asongan dengan kotak dagangan mondar-mandir di dalam kedua gerbang pagar (06–22, berpayung saat hujan).
- **Papan jadwal** (`src/game/papan-jadwal3d.ts`): papan besar di aula dan papan jadwal digital di ruang tunggu menampilkan jam terminal dan bus yang benar-benar ada: jam berangkat ditetapkan sekali saat bus diparkir (perkiraan sisa cuci + menunggu jadwal + ke halte + ngetem, dibulatkan ke atas per 5 menit), lalu kolom JALUR dan STATUS mengikuti keadaan bus: PERSIAPAN, SIAP (menuju jalur), NAIK, BERANGKAT, atau TERLAMBAT bila jamnya lewat sebelum bus mulai memuat.
- **Pengantar** (`src/game/rombongan.ts`): ±5 % penumpang diantar sampai gerbang keberangkatan (ikut antre, duduk di sebelahnya di ruang tunggu). Begitu penumpangnya keluar gerbang, pengantar berhenti di dalam ruang tunggu di samping gerbang dan melambaikan tangan sampai busnya berangkat, lalu pulang lewat aula dan gerbang pagar MASUK.

## Jam terminal, hari, siang–malam, cuaca

- **Jam 24 jam & hari Senin–Minggu** (`src/sim/waktu.ts`): diturunkan dari waktu main aktif (`statistik.waktuMainDetik`), jadi ikut tersimpan di save tanpa mengubah format save. Jam berhenti saat game ditutup. Game baru mulai **Senin 06:00**. HUD kanan atas menampilkan ikon matahari/bulan, nama hari (Minggu berwarna merah), dan jam `HH:MM`.
- **Kecepatan waktu 1× / 2× / 3×**: tombol di bawah jam HUD (atau tombol keyboard 1, 2, 3); pilihannya disimpan (`terminal-bus-tycoon/kecepatan`). Seluruh permainan berjalan sekian kali lebih cepat: jam terminal, bus, orang, lalu lintas, cuaca, dan simulasi ekonomi (pendapatan per detik nyata ikut ×2/×3). Penghasilan offline tetap dihitung dari waktu nyata, autosave tetap tiap 10 detik nyata, dan efek visual yang terasa janggal bila dipercepat (tetes hujan, kedip lampu, kibar bendera, kamera, jeda pengumuman) tetap waktu nyata. Simulasi keramaian dijalankan dalam langkah ≤ 0,05 detik main supaya tetap stabil. Pilihan di `PILIHAN_KECEPATAN` (`src/config/waktu.config.ts`).
- **Skala waktu** di `src/config/waktu.config.ts`: `detikPerJam` (bawaan 60, jadi satu hari terminal = 24 menit nyata dan sepekan ≈ 2,8 jam), `jamAwal`, `jamTerbit`, `jamTerbenam`. Selain `detikPerJam` (yang ikut menentukan lamanya jam sepi, lihat ritme), semuanya murni tampilan.
- **Siang–malam** (`src/game/langit.ts`, murni dan dites): titik kunci suasana dari fajar, pagi, siang, sore, senja, sampai malam diinterpolasi halus. Matahari terbit di timur dan terbenam di barat. Di malam hari cahaya utama berganti ke bulan kebiruan. Pergantian matahari ↔ bulan terjadi saat cahaya padam, jadi bayangan tidak melompat. Tingkat malam menyalakan lampu jalan (dengan genangan cahaya di tanah, `src/game/cahaya3d.ts`), jendela gedung kota, lantai & kaca aula terminal, papan nama, papan jadwal, serta lampu depan & belakang bus beserta sorotnya di aspal. Semua hanya mengubah `emissiveIntensity` dan warna cahaya, jadi shader tidak dikompilasi ulang.
- **Ritme keramaian harian** (`keramaianTerminal` di `src/sim/waktu.ts`, kurva di `RITME` `src/config/waktu.config.ts`): jam sibuk pagi (±06–09) dan sore (±16–19), sepi dini hari, sedang di siang hari. Per hari: Senin pagi (arus balik), Jumat sore & Minggu sore lebih ramai, Sabtu siang agak ramai, Minggu pagi lengang. HUD menampilkan pil **Jam sibuk / Ramai / Sedang / Sepi** di bawah jam. Ritme mengatur **permintaan**: di adegan (`terapkanRitme` di `src/game/laju.ts`) bus datang lebih jarang dan lebih kosong saat sepi sehingga calon penumpang juga lebih sedikit; di ekonomi versi yang dilandaikan (`EKONOMI.permintaan.ritmeMin`) menurunkan arus & pendapatan di jam sepi (lihat Kepuasan penumpang). Kapasitas tiap tahap tidak berubah, jadi antrean menumpuk di bottleneck saat jam sibuk lalu surut saat sepi, dan bus malam tetap bisa berangkat penuh mengangkut sisa penumpang (kursinya tetap). Pengunjung yang duduk di aula, yang makan, dan anak di taman berkurang saat sepi (sebagian tetap menunggu bus subuh), begitu juga lalu lintas & pejalan kaki di luar (berganti hanya saat membungkus di ujung jalan, di luar layar).
- **Cuaca** (`src/sim/cuaca.ts`, angka di `src/config/cuaca.config.ts`): tiap pekan Senin–Minggu diacak **1–3 hari hujan** (bobot 30/45/25 %), masing-masing sekali di **pagi** (05–09, gerimis sampai sedang), **siang** (11.30–15.30, paling deras, sering berpetir), atau **malam** (18.30–21.30), dan selalu reda sebelum ganti hari. Acakannya memakai benih cuaca (`benihCuaca`) yang dibuat sekali saat game baru dan ikut disimpan di save: jadwal hujan berbeda di tiap game, tapi tidak berubah saat game ditutup lalu dibuka lagi (save lama otomatis diberi benih saat dimuat). Hari pertama tidak memilih hujan pagi yang sudah lewat sebelum game dimulai. Langit mendung dulu ±1 jam sebelum hujan. Efeknya (`src/game/hujan3d.ts`, `terapkanCuaca` di `langit.ts`): langit & kabut kelabu, matahari meredup sehingga bayangan melunak, lampu ikut menyala sebagian; butiran hujan miring tertiup angin (digerakkan di vertex shader) yang berhenti di atap kaca terminal; cipratan cincin di aspal & paving; tanah, marka, rumput, dan genteng menggelap basah lalu mengering perlahan (±2 jam terminal) dengan genangan mengilap; lampu bus menyala; pejalan kaki di trotoar berkurang; orang di luar atap membuka payung warna-warni (±15 % menerobos tanpa payung, anak berlindung di payung orang tuanya), pengunjung di luar berteduh, petugas di luar berjaga berpayung. Saat hujan deras, kilat petir sesekali menerangi langit disusul guntur. HUD menampilkan ikon awan hujan.

## Tampilan layar (portrait & landscape)

Overlay DOM dirancang dalam piksel logis lalu di-scale supaya selalu **mengisi layar penuh** tanpa pita kosong (`src/ui/bingkai.ts`):

- **Portrait**: lebar logis 720, tinggi mengikuti layar. HUD ringkas di atas (uang, pendapatan, arus, pil tipe terminal & kepuasan; jam, hari, keramaian), adegan 3D di tengah, tiga kartu tahap di bawah (satu baris: ikon, info, tombol).
- **Landscape**: tinggi logis 720, lebar mengikuti layar. Adegan 3D di kiri, bilah samping kanan berisi HUD lalu tiga kartu tahap bertumpuk (info di atas, tombol sebaris di bawah).
- Skala dibatasi 1,1× supaya teks tidak membesar berlebihan di monitor lebar; sisa ruang dipakai tata letak (CSS flex di `src/ui/gaya.css`, kelas `#ui.potret` / `#ui.lanskap`). Wadah canvas 3D ditempatkan tepat di atas kotak `.area-adegan`, jadi selalu pas walau tinggi HUD/panel berubah (mis. baris petunjuk muncul).
- Tema gelap menyatu untuk HUD, kartu tahap (aksen warna & ikon per tahap, sorotan merah berdenyut untuk tahap paling lambat), dan popup offline. Tombol suara & kamera melayang di pojok kanan atas adegan.
- **Panel ringkas**: tombol "Ringkas" melipat panel menjadi **rel ikon**, satu lingkaran bercincin warna tahap, dengan level di bawahnya. Tanda "!" merah berarti paling lambat, dan panah hijau berarti upgrade atau Kepala sudah terjangkau. Mengetuk ikon membuka panel penuh. HUD ikut diringkas: uang, pendapatan singkat, jam, dan kecepatan. Di landscape bilah samping menyempit dari 400 ke 152, di portrait rel berada di bawah. Tombol buka panel hanya panah (titik merah bila ada hadiah untuk diklaim). Popup offline ditutup dengan "Ambil", mengetuk area gelap di luarnya, atau Esc. Pilihannya disimpan (`terminal-bus-tycoon/panel`).
- **Label tahap di peta** (`src/game/zona3d.ts`): nama tahap, lencana "K" bila tahapnya sudah punya Kepala, dan "⚠ PALING LAMBAT" di atas tahap bottleneck (lantainya disorot merah berdenyut). Semua tahap selalu berjalan, jadi label hanya penanda: tidak bisa diketuk, dan geser kamera melewatinya.
- Saat layar diputar, kamera dibingkai ulang: landscape memuat seluruh terminal, portrait memuat inti terminal (pangkalan, gedung, ruang tunggu; peron kedatangan tinggal digeser).

## Tampilan 3D (three.js)

Terminal dirender sebagai adegan 3D dengan kesan foto maket: kamera perspektif sempit dengan elevasi 42° (sudut hampir isometrik), matahari dengan bayangan lembut, cahaya langit, pantulan langit di kaca dan bodi bus, serta post-processing (ambient occlusion N8AO, bloom, tilt-shift, tone mapping ACES, vignette, SMAA).

- **Kamera:** geser dengan drag. Zoom dengan cubit dua jari (HP) atau roda mouse (desktop), mengarah ke titik yang ditunjuk. Zoom bisa cukup dekat untuk melihat orang dan bus. Tampilan awal otomatis memuat seluruh inti terminal. Tilt-shift melemah saat kamera mendekat.
- **Putar kamera:** di HP, pelintir dua jari (peta berputar mengikuti jari; pelintiran di bawah 9° diabaikan supaya cubit zoom tidak ikut memutar, `src/game/kamera.ts`). Di desktop, klik kanan (atau Shift/Ctrl + klik kiri) lalu seret untuk memutar sekaligus memiringkan; tombol Q/E memutar 45°. Tombol di pojok kanan atas area adegan: putar kiri/kanan 45° (beranimasi) dan kompas yang jarum merahnya selalu menunjuk utara; ketuk kompas untuk kembali ke arah & kemiringan awal. Kemiringan dibatasi 25°–75° dari tanah.
- **Denah** (`src/game/tata-letak.ts`, 1 unit = 1 petak ≈ 5 m):
  - jalan raya bermedian dengan gapura masuk/keluar dan pos retribusi
  - jalan dalam satu arah (lajur halte + lajur sirkulasi); di kedua ujungnya jalur belok beraspal berkerb melewati bukaan median (masuk di barat, keluar di timur), jadi bus tidak melintas di atas paving/rumput
  - peron kedatangan berkanopi kaca lengkung dengan **5 halte** (berjarak 3,6 petak) di ujung barat, taman kota di belakangnya. Halte keberangkatan berjarak 4 petak. Celah antarbus yang berhenti cukup untuk bus belakang berbelok keluar ke lajur sirkulasi tanpa menyenggol bus di depannya (dites, sisa ruang ≥ 0,35)
  - pangkalan bus parkir serong berisi **20 petak** (jarak 1,25; tes memastikan bus yang parkir, masuk, dan keluar petak tidak menyenggol bus di petak sebelahnya), **dikelompokkan per jurusan** keberangkatan: empat kelompok × 5 petak (`KELOMPOK_PARKIR` di `tata-letak.ts`: JAKARTA · BANDUNG, SEMARANG · YOGYAKARTA, SOLO · MALANG, SURABAYA · DENPASAR), masing-masing diawali **pulau taman bertiang papan jurusan** di tengah pangkalan (menempati satu posisi petak, jadi bus yang keluar-masuk petak sebelahnya tidak menyenggolnya; dites) dengan papan bersilang serong empat muka yang menjulang di atas atap bus, sehingga terbaca dari arah kamera mana pun dan tidak tertutup gedung, plus tanda lantai sewarna di tiap petak. Pangkalan sekaligus **tempat cuci bus**: saluran air di tiap petak dan pos cuci (papan "CUCI BUS", tandon air, gulungan selang, lampu sorot) di ujung timur
  - **terminal terpadu** (`src/game/gedung3d.ts`): gedung utama berupa aula kaca yang isinya terlihat dari kamera. Atapnya lengkung kaca berusuk baja putih dengan tritisan logam, fasadnya tirai kaca bening. Di depannya ada selasar bertiang, gapura "TERMINAL TERPADU", bordes landai di pintu masuk, dan atrium kaca berjam di atas pintu
  - **aula loket** di dalam gedung utama: delapan jendela loket tiket di dinding utara (meja berwarna tahap loket, kaca loket, petugas di baliknya, papan nomor & kota tujuan, papan "LOKET TIKET BUS"), labirin antrean di depannya (tali sabuk bertiang keliling dan di antara lajur, celah belokan bergantian di barat dan timur, dua baris per lajur), minimarket, apotek, ATM center, dua pintu di dinding barat ke sayap barat (bagian bawah dinding masif, di atasnya kaca supaya isi sayap barat terlihat), deretan kursi, meja informasi, papan jadwal besar, dan penunjuk arah ke ruang tunggu. Dinding dalam tidak membuang bayangan supaya deretan loket tetap terang
  - **sayap barat** (`src/game/sayap3d.ts`, denah & titik singgah di `tata-letak.ts`): bangunan beratap kaca yang menempel dinding barat aula di tepi taman. Isinya lorong di sepanjang dinding aula, **toilet pria** (bilik berpintu biru, urinoir, wastafel berkaca), **toilet wanita** (bilik berpintu merah muda, wastafel), serta **tempat wudhu** (keran berderet, saluran air) dan **musholla** untuk pria dan wanita (karpet hijau, sajadah per shaf menghadap kiblat di barat, mihrab, rak alas kaki). Sekat antarruangan rendah dan fasad selatannya kaca, supaya isinya terlihat dari kamera. Papan "TOILET" & "MUSHOLLA" di atas pintunya di aula.
  - **ruang tunggu keberangkatan** yang menyatu dengan ujung timur gedung utama: aula berdinding & beratap kaca (rusuk baja putih), 240 kursi dalam empat blok, kios, meja makan, papan jadwal digital, dan **lima gerbang** "JALUR 1–5" yang langsung membuka ke peron keberangkatan (5 halte), tepat di depan pintu bus di tiap halte
  - plaza dengan air mancur, taman, dan parkir mobil & motor
- **Sekitar terminal** (`src/game/sekitar3d.ts`, `src/game/lingkungan3d.ts`): kota berlapis dengan masjid, jalan lingkungan dua arah dengan lalu lintas mobil/angkot/motor (`src/game/lalu-lintas.ts`), deretan ruko berpapan nama, kampung beratap genteng, SPBU, tiang listrik berkabel, dan pejalan kaki di trotoar.
- **Keramaian** (`src/game/dunia-visual.ts`) adalah model *dekoratif*, bukan simulasi ekonomi. Siklus bus: masuk → turunkan penumpang → parkir serong & dicuci → ngetem di halte keberangkatan → keluar. **Cuci bus**: bus tiba berdebu (badannya kusam). Di petak parkir, kenek turun dari pintu depan dan mengelilingi bus sambil menyabun (gumpalan busa muncul mengikuti langkahnya); sopir (kemeja putih, bertopi) turun menyusul dan mengelilingi bus sambil membilas (semprotan air, busa luntur, debu hilang), lalu keduanya naik lagi. Petak lalu basah dan mengering perlahan (`src/game/cuci3d.ts`). Bus baru boleh berangkat setelah bersih, lalu menunggu jadwal jurusannya selama `ISTIRAHAT_DETIK` (45 detik, sopir & kenek istirahat), jadi pangkalan biasanya berisi ±8–10 bus dan bisa penuh 20 bus bila keberangkatan lambat. **Peron kedatangan**: semua bus yang berhenti di samping peron menurunkan penumpang bersamaan (bergiliran; laju turun total tetap laju tahap peron, jadi peron yang lambat tetap terlihat sebagai bottleneck), dan bus tidak bergerak selama penumpangnya turun. Isi bus yang datang bervariasi ±30 %, jadi bus yang lebih kosong selesai lebih dulu: ia langsung berangkat, dan bila bus di depannya masih menurunkan penumpang ia mendahului lewat lajur sirkulasi. Bus yang baru datang langsung mengisi halte kosong **terdepan**. Bila bus di belakang halte itu masih menurunkan penumpang, bus baru masuk ke lajur sirkulasi, menyalipnya, lalu berbelok masuk tepat di depannya (`ruteKeHalteDatang`, dites bebas senggolan walau semua halte lain terisi). Bus baru menunggu di jalan raya hanya bila kelima halte terisi. Di halte keberangkatan, bus belakang yang sudah penuh (atau habis waktu ngetem) mendahului bus yang masih memuat di depannya. Saat berbelok, bus hanya memperhitungkan bus di lajur tujuannya (`ruangDepan` di `dunia-visual.ts`). Bus yang selesai menurunkan penumpang ditugaskan ke jurusan yang kelompok petaknya paling lowong (seri diundi, supaya semua kelompok terisi), parkir di salah satu petak kosong kelompok itu, dan pengumuman keberangkatannya menyebut jurusan tersebut. Lama cuci `CUCI.detik` (21 detik: tiap petugas berjalan dengan laju jalan biasa) ada di `tata-letak.ts`; karena pangkalan biasanya berisi beberapa bus, cuci tidak menurunkan arus keberangkatan. Penumpang mengalir dalam dua arus terpisah. **Penumpang turun** berjalan dari peron kedatangan lewat jalur pejalan kaki di sisi barat gedung, keluar lewat gerbang "PINTU KELUAR" di pagar belakang, lalu lewat gang di sela ruko ke trotoar jalan belakang (pulang). Mereka tidak pernah antre lagi. **Calon penumpang** datang dari luar, yaitu dari trotoar jalan belakang lewat gerbang "PINTU MASUK" atau dari parkir mobil. Mereka memilih baris yang lebih pendek, masuk lewat pintu gedung dan celah tali di pojok labirin, lalu **menyusuri lajur labirin yang berkelok** (lintasan `JALUR_ANTREAN` di `tata-letak.ts`) sampai ujung barisnya, sama seperti yang sudah antre. Tidak ada yang memotong antarlajur, dan pejalan di baris yang sama menjaga jarak satu slot supaya tidak berhimpit. Urutan antrean baru diambil saat tiba, jadi yang masih berjalan tidak dihitung antre dan labirin hanya penuh kalau loket memang lambat. Yang sudah antre maju menyusuri lajur yang sama (dua baris berdampingan) tanpa menembus tali. Bila labirin penuh, antrean meluap keluar pintu dan berbaris di depan fasad. Kepala antrean dipanggil ke jendela loket yang paling sepi dengan laju loket. Urutan antre didahulukan, tapi bila orang terdepan satu baris masih melangkah maju, orang terdepan baris sebelahnya yang sudah siap dipanggil duluan (`kepalaSiap`), seperti antrean dua baris sungguhan; tanpa ini, orang yang tiba bergerombol per baris membuat satu baris menunggu baris lain maju selangkah demi selangkah dan antrean menumpuk di loket yang sebenarnya longgar (paling banyak 5 pembeli per jendela: satu bertransaksi, dua menunggu di belakangnya, dua di kiri-kanan saat ramai). **Transaksi di jendela tidak instan**: petugas santai selama arus calon penumpang mengizinkan (±2,5–7 detik, bervariasi per pembeli), lalu bergegas saat antrean mulai menumpuk (mis. dua bus menurunkan penumpang sekaligus) sampai sanggup mengikuti laju loket penuh, jadi deretan jendela tidak menjadi hambatan palsu. Supaya transaksi bisa sepanjang itu, arus visual dibatasi ±0,24 orang/detik per jendela yang buka (`batasArusJurusan` di `laju.ts`): terminal dengan sedikit jurusan tampak lebih sepi dan makin ramai tiap jurusan baru dibuka. **Mampir**: ±1/3 pembeli yang bepergian sendiri mampir dulu setelah membeli tiket: ke toilet (bilik atau urinoir, lalu wastafel; pria & wanita ke ruangnya masing-masing, dilihat dari jilbab), ke musholla (wudhu lalu sholat: berdiri dan duduk bergantian menghadap kiblat; jauh lebih ramai ±50 menit setelah awal waktu sholat), ke ATM center, atau ke minimarket/apotek yang sedang buka (setelah Kios & Minimarket dibangun). Penumpang yang sudah duduk sesekali bangun ke kios ruang tunggu (kopi, roti, oleh-oleh) lalu kembali ke kursinya. Tiap bilik, keran, sajadah, mesin ATM, dan tempat berdiri di toko/kios dipakai satu orang; kursinya tetap dipesan dan ia baru bisa dipanggil ke bus setelah duduk lagi. Setelah membeli tiket, mereka berjalan menyusuri aula ke pintu ruang tunggu, lalu duduk di kursi (kursi dipilih menyebar, baris depan lebih disukai). Saat loket berhenti, jendela kosong dan antrean tertahan. Penumpang dipanggil sejak busnya keluar pangkalan, berdiri dan berkumpul di balik gerbang. Setelah bus berhenti, mereka keluar gerbang dan naik lewat pintu depan. Bus menunggu sampai penumpang yang sudah dipanggil naik semua. **Bus di halte keberangkatan tidak pernah maju** ke halte depan yang kosong (penumpang tidak bingung pindah gerbang); sebaliknya bus dari pangkalan langsung mengisi halte kosong mana pun (terdepan dulu): halte paling belakang lewat lajur halte, halte lain lewat lajur sirkulasi lalu berbelok masuk, walau halte di belakangnya terisi (`ruteKeHalteBerangkat`, dites bebas dari bus di semua halte lain). Jumlah calon penumpang yang datang mengikuti jumlah penumpang yang turun, dan loket berjalan relatif terhadap arus nyata itu. Karena itu kerumunan tetap menumpuk tepat di depan tahap yang paling lambat, walau jumlah bus dibatasi manuvernya. Muatan per bus naik seiring throughput (12–20 penumpang). **Rombongan** (`src/game/rombongan.ts`): ±20 % penumpang bepergian bersama anak atau pendamping dewasa. Anggota rombongan bukan agen tersendiri (tidak memakai slot antrean atau jendela loket): ia menapak jejak pemimpinnya sedikit di belakang-samping seperti bergandengan tangan, sehingga tidak menembus tali labirin. Di ruang tunggu mereka duduk berdampingan di kursi sebelah yang dipesankan saat membeli tiket, dan kursinya dilepas saat naik bus. Semua gerak maju dengan kurva halus, dan bus menjaga jarak dengan bus di depannya. Lajunya diturunkan dari state sim (`src/game/laju.ts`): tahap paling lambat berjalan paling pelan, sehingga **antrean orang menumpuk tepat di depan bottleneck**. **Laju jalan alami**: semua orang berjalan `KECEPATAN_JALAN` = 0,45 petak/detik (sama dengan pejalan kaki di trotoar, ±12% per orang, ±2,6 langkah/detik). Karena itu tiap orang lebih lama di layar dan kerumunan lebih ramai (batas `MAKS_ORANG` 480), sedangkan arus visual dibatasi `LAJU_MAKS` 1,8 orang/detik di `laju.ts` supaya tetap di bawah daya tampung jalan kaki (antrean dua baris, jendela loket, gerbang) dan tidak muncul hambatan palsu. Arus visual ini sudah lama berupa gambaran (dikompres logaritmik dari angka HUD); ekonomi tidak berubah.
- **Loader kemajuan bus** (`src/game/label-bus.ts`, murni dan dites; digambar `src/game/label-bus3d.ts`): di **peron kedatangan**, bus yang menurunkan penumpang berlabel "TURUN 7/16" (penumpang turun / penumpang yang dibawa, `muatanDatang`) dengan bilah berwarna tahap peron. Di **petak parkir jurusan**, bus yang sedang dicuci berlabel cincin loader berwarna jurusannya dengan ikon tetes air, yang berubah jadi centang hijau saat bersih. Bentuknya ringkas karena petak parkir berdempetan. Di **jendela loket**, pembeli yang sedang membeli tiket mendapat cincin loader berwarna tahap loket dengan ikon tiket (kemajuan dari `lamaTimer` transaksi, `src/game/label-loket.ts`); centang singkat saat tiket selesai dibeli, lalu cincin berikutnya mulai untuk pembeli berikutnya. Cincin loket disembunyikan bila kamera terlalu jauh sehingga cincin jendela bersebelahan bertumpuk. Semua loader memudar sebentar setelah selesai. **Label keberangkatan**: saat bus mulai memuat di halte keberangkatan, di atasnya muncul label jurusan dan **penumpang naik / kapasitas bus** (mis. "SURABAYA 12/19") dengan bilah kemajuan: bagian penuh = sudah masuk pintu, bagian samar = sudah dipanggil dan sedang berjalan ke bus. Label hijau saat penuh, bertahan sebentar setelah bus berangkat, dan mengecil saat kamera menjauh supaya label di halte bersebelahan tidak saling menutupi.
- **Efek "+Rp"** (`src/game/kas-visual.ts`, murni dan dites; digambar `src/game/pop-uang3d.ts`): uang yang masuk menurut sim tampil di tempat transaksinya: di atas **jendela loket** saat tiket terjual (ikon tiket), di atas **bus yang baru parkir** di petak (retribusi, ikon bus), di **lorong parkir** saat calon penumpang turun dari kendaraan pengantar (ikon P), dan di **kios/toko** saat penumpang selesai belanja (ungu: masuk omzet, belum uang). Saat hari berganti, sewa kios yang dibayar tampil sebagai "+Rp" emas besar di deretan kios ruang tunggu. Keramaian hanya wakil arus penumpang sim, jadi besar tiap "+Rp" = pendapatan per detik sumber itu ÷ rata-rata transaksi yang terlihat per detik, ditambah koreksi kecil dari selisih yang terkumpul: angkanya stabil, ikut membesar seiring terminal berkembang, dan totalnya sama dengan uang yang masuk. Lompatan waktu (muat save, tab tertidur) tidak dibagikan karena sudah masuk laporan offline. Efek naik lalu memudar (±1,5 detik), mengecil saat kamera menjauh, dan tidak naik bila pemain memilih kurangi gerak.
- **Klakson telolet** (`src/game/telolet.ts`, murni dan dites; spanduk `src/game/telolet3d.ts`): ketuk bus mana pun (di jalan, halte, atau pangkalan) untuk membunyikan klakson telolet; label "♪ TELOLET!" muncul dan ikut bergerak bersama busnya. Ketukan dibedakan dari geser/zoom kamera (bergeser < 8 px, < 0,4 detik); bus yang sama baru bisa berbunyi lagi setelah 1,6 detik. Pukul 07.00–17.30 (tidak saat hujan) tiga anak berdiri di trotoar seberang jalan raya, dua mengangkat spanduk kardus "OM TELOLET OM"; mereka melambai ke tiap bus yang lewat di depannya, dan melompat kegirangan sambil melambai ±3 detik saat telolet berbunyi dalam jarak 26 petak.
- **Livery mitra PO** (`src/config/livery.config.ts` warna/pola/tulisan, `src/game/livery.ts` murni dan dites, digambar `src/game/kendaraan3d.ts`): dibuat dari gambar samping atlas (varian 1 = `bus/oranye-1`, varian 2 = `bus/kuning-2`) yang piksel cat badannya dikenali lewat rona lalu diwarnai ulang ke warna PO dengan bayangan & sorotan dipertahankan; pola aksen (garis di atas jendela, dua warna di badan bawah, atau sapuan miring) hanya mengenai cat badan, dan nama PO ditulis besar di pita atas kedua sisi (dipotong ke cat badan, jadi terputus di pintu seperti stiker) serta di papan tujuan depan. Bus terminal yang baru muncul memakai livery bawaan atau livery PO yang terdaftar (tiap PO berbobot 2), dan tetap memakai livery itu sampai pergi.
- **Tanda kelas terminal** (`src/game/kelas3d.ts`): papan nama balok gapura berganti TERMINAL TIPE C (abu-abu) → TIPE B (biru) → TIPE A (gelap bertulisan emas) → TERMINAL TERPADU (cokelat emas), atau "TERMINAL <NAMA>" dengan tipe di baris kedua bila pemain menamai terminalnya (papan dibuat ulang hanya saat nama/kelas berubah); mulai Tipe B umbul-umbul warna-warni berkain bergelombang berdiri di sepanjang median jalan raya (tidak di bukaan & tiang lampu), mulai Tipe A lampu hias melendut di antaranya dan menyala di malam hari, dan kelas Terpadu mendapat bintang emas di atas gapura (satu per bintang, maks. 5).
- **Foto terminal** (`src/ui/foto.ts`, tombol kamera di kolom kontrol, web saja): memotret adegan 3D tanpa label & tombol (render sekali lalu disalin sebelum kanvas WebGL dibersihkan), menambahkan bingkai bawah berisi ikon & nama game, keterangan terminal pemain (jurusan, penumpang/detik, mitra PO), dan "Main gratis di bustation.games", lalu menawarkan **Bagikan** (Web Share API dengan berkas, umumnya di HP) atau **Simpan gambar** (unduh JPEG). Atur kamera dulu untuk memilih sudut. Analitik: `foto_terminal`, `share` (method `web_share`/`unduh`). Belum untuk APK (WebView Android tidak punya Web Share).
- **Mode sinema** (video promosi; tombol papan klapper di kolom kontrol, `src/ui/sinema.ts`; kamera `src/game/sinema.ts` murni dan dites): popup memilih kecepatan waktu (1 hari ≈ 1 menit, ≈ 3 menit, atau asli) dan cuaca (sesuai jadwal, cerah, hujan), lalu semua tampilan & label disembunyikan dan adegan memenuhi layar (9:16 di HP), kamera berputar pelan mengelilingi titik pandang saat itu (satu putaran 150 detik, zoom ±10 %, miring & geser sepanjang terminal "bernapas", mulai tanpa lompatan), dan hanya ada tanda kecil "bustation.games · jam" di pojok. Rekam dengan perekam layar HP untuk TikTok/Reels. Hanya tampilan yang dipercepat (`OpsiSinema` di `src/game/terminal3d.ts`: jam tampilan = jam main + selisih, kerumunan 2–4×); ekonomi di state tetap berjalan dengan kecepatan game biasa, jadi mode ini tidak bisa dipakai untuk mempercepat penghasilan. Ketuk layar atau Esc untuk keluar: kamera & jam kembali seperti semula.
- **Bus** (`src/game/kendaraan3d.ts`): badan satu `InstancedMesh` dengan atap melengkung dan spion. Kaca mengilap dan cat doff lewat peta kekasaran yang dibuat otomatis dari tekstur. Roda 3D berputar sesuai jarak tempuh. Pintu depan berengsel terbuka saat bus menurunkan atau menaikkan penumpang di halte. Pintu bagasi di antara roda (sisi peron, `BAGASI` di `tata-letak.ts`) diangkat selama bus di halte, dengan koper, kardus, dan tas di sampingnya dan kenek berjaga (kenek yang sama nanti mencuci bus). Posisi pintu (`PINTU_BUS` di `tata-letak.ts`) sama dengan titik naik/turun penumpang di `DuniaVisual`. Lampu rem menyala saat melambat atau berhenti, lampu sein berkedip saat berbelok, dan badan bus sedikit menunduk saat mengerem.
- **Orang** (`src/game/orang3d.ts`): orang 3D low-poly, sepuluh `InstancedMesh` untuk seluruh kerumunan. Mereka menghadap arah jalan, kaki dan lengan berayun sesuai jarak tempuh, dan penampilannya beragam (kulit, baju, celana, rambut, jilbab dan gamis, ransel, topi, tinggi badan, anak-anak). Sebagian menarik **koper beroda** (miring saat ditarik, tegak di samping saat berhenti atau duduk); saat hujan di luar atap, payung terbuka di atas kepala. Penumpang di ruang tunggu duduk menghadap gerbang. Satpam, polisi, petugas gerbang, penjual kios, pengunjung yang makan, orang duduk di bangku, dan anak di taman adalah orang statis. Mesin tiket, papan jadwal, mobil golf, dan anjing juga dibuat 3D.
- **Ambient occlusion**: di tingkat kualitas tertinggi dipakai N8AO (`n8ao`), yaitu kontak bayangan di sudut dinding, kolong bus, dan celah antar-rumah. N8AO memakan 7–10 ms per frame di Intel Iris Xe, jadi tingkat lain memakai bayangan kontak yang dipanggang di bawah gedung, rumah, dan mobil (`bayanganKontak` di `src/game/geometri.ts`), ditambah bayangan kolong di bawah kendaraan yang bergerak.
- **Material**: tekstur prosedural Canvas 2D (`src/game/tekstur3d.ts`) untuk rumput, aspal, paving, genteng, bata, plester, fasad kota, atap logam, dinding tirai kaca, lantai granit, dan papan jadwal. Atap & dinding kaca ruang tunggu memakai material transparan supaya isinya terlihat dari kamera. Variasi warna skala besar per posisi dunia mencegah pola tekstur yang berulang. Semua papan nama berbagi atlas teks 2048²; papan bertulisan & bergaya sama memakai tempat yang sama, dan bila atlas penuh halaman baru dibuat otomatis (tidak menggagalkan pemuatan adegan).
- **Bayangan mengikuti kamera** (`src/game/bayangan.ts`, murni dan dites): peta bayangan matahari dipasang di atas tanah yang sedang terlihat, bukan di satu area tetap. Pojok-pojok layar diproyeksikan ke tanah, lalu dibungkus persegi di bidang tegak lurus arah cahaya (setengah sisi 12–64 unit, dibulatkan per 4 unit). Makin dekat kamera, bayangan makin tajam, dan seluruh peta termasuk peron kedatangan & taman kini ikut berbayangan. Pusatnya digeser per texel supaya tepi bayangan tidak berkilau saat kamera digeser. Normal bias mengikuti ukuran texel. Di HP, peta bayangan digambar ulang tiap 2–3 frame, tapi tetap langsung saat kamera atau matahari bergeser.
- **Langit & pantulan** (`src/game/langit3d.ts`): langit prosedural (gradasi zenit → cakrawala, pendar & piringan matahari, bulan, awan yang menebal saat mendung, pendar lampu kota di cakrawala malam) dirender ke cube map 128 px dan dipakai sebagai environment map. Kaca, bodi bus, fasad kota, dan genangan memantulkan langit sesuai jam dan cuaca: biru di siang hari, jingga saat senja, kelabu saat hujan, gelap kekuningan di malam hari. Matahari yang terpantul di kaca atap tampak sebagai kilau. Cube map hanya dibuat ulang bila langit berubah cukup jelas (paling cepat tiap 1,2 detik), ke tekstur yang sama, jadi material tidak berganti shader. Kekuatan pantulan tetap mengikuti `intensitasLingkungan` suasana, dibagi perkiraan kecerahan langit, jadi langit malam yang hampir hitam tidak membuat bangunan gelap gulita. Warna zenit (`warnaZenit`), benda langit, mendung, dan kilat ada di `Suasana` (`langit.ts`).
- **Bloom**: lampu jalan, jendela kota, papan menyala, lampu depan/rem/sein bus (warna HDR di atas putih), dan kilau matahari di kaca berpendar. Ambang bloom turun dan kekuatannya naik di malam hari. Di siang hari hanya kilau terkuat yang berpendar; kilat petir memperkuatnya sesaat.
- **Kaca & kanopi transparan dua sisi** memakai `forceSinglePass`. Tanpa itu three.js menggambarnya dua kali dan mengevaluasi ulang program shader tiap frame, salah satu beban CPU terbesar sebelum diperbaiki.
- **Kualitas adaptif** (`src/game/adegan.ts`): kalau frame lambat, kualitas turun bertahap, mulai dari rasio piksel, lalu AO, multisampling, ukuran & frekuensi peta bayangan, bloom, dan tilt-shift. Tingkat tanpa multisampling memakai SMAA (pass terpisah setelah tone mapping). Tingkat terendah tanpa bayangan dan tanpa post-processing. Shader dikompilasi sebelum frame pertama supaya tidak tersendat. Di mode dev, jumlah draw call dan segitiga dicatat ke console, dan `?tingkat=0..4` di URL mengunci tingkat kualitas untuk mengukur performa.
- Adegan 3D dimuat terpisah (dynamic import). UI dan simulasi sudah berjalan sebelum grafis siap. Kalau WebGL2 tidak tersedia, muncul pesan dan game tetap bisa dimainkan lewat panel.

## Suara

Semua bunyi disintesis dengan Web Audio (derau + osilator), tanpa file audio, jadi APK tidak membesar.

- **Lapisan latar** (kekerasan diatur tiap frame): riuh orang (celoteh dari derau berformant), mesin diesel bus yang langsam/melaju (mesin dimatikan saat parkir dicuci), gemuruh lalu lintas, semprotan air cuci, jangkrik di malam yang sepi, dan hujan.
- **Bunyi sesaat**: desis rem angin saat bus berhenti, deru mesin saat bus berangkat (kadang disertai klakson "tin-tin"), klakson kendaraan di jalan, guntur yang menyusul kilat, dan **klakson telolet** saat pemain mengetuk bus (empat melodi terompet angin, tiap bus selalu memakai melodi yang sama).
- **Pengumuman**: bel "ting-tung" (empat nada, bergema seperti di aula) lalu kalimat bahasa Indonesia, misalnya "Perhatian. Bus jurusan Surabaya sudah siap di jalur 2. Penumpang dipersilakan naik." Nomor jalur sama dengan papan "JALUR" di gerbang. Sesekali ada pengumuman kedatangan dan pengumuman umum (jaga barang bawaan, dilarang merokok, waspada calo). Jaraknya minimal 35 detik. Kalimat diucapkan dengan `speechSynthesis` bila perangkat punya suara bahasa Indonesia (mis. Chrome desktop, "Google Bahasa Indonesia"); kalau tidak (sebagian WebView Android), hanya bel.
- **Seperti dari kamera**: sumber di dekat titik pandang lebih keras, yang jauh samar, zoom masuk mendekatkan suara, dan bunyi sesaat diposisikan kiri–kanan (stereo) sesuai letaknya di layar.
- Tombol speaker di pojok kanan atas area adegan menyalakan/mematikan suara; pilihannya disimpan (`terminal-bus-tycoon/suara`). Aturan autoplay browser/WebView: suara baru mulai setelah sentuhan pertama. Suara berhenti saat app di-pause.
- Logika murni (kekerasan tiap lapisan, kejadian, teks pengumuman) ada di `src/game/suara.ts` dan dites; mesin Web Audio di `src/platform/suara.ts` (volume tiap lapisan di `MAKS_LAPISAN`).

Sumbernya satu lembar `assets/master.jpg`. Untuk memotongnya menjadi aset terpisah dan menyusun atlas game:


Keluarannya:

Untuk menambah aset, tulis kotaknya di sana lalu jalankan ulang `npm run aset`. `tests/aset.test.ts` memeriksa atlas tetap konsisten dengan `aset-data.ts`. Cara pakai di game:

- **Bus**: gambar tampak samping ditempel ke sisi kanan dan kiri (dicerminkan) balok bus 3D lewat "lembar bus" (bus kota ekonomi & patas; kelas lain dilukis prosedural). Muka depan (kaca, papan trayek, lampu, pelat nomor), belakang, dan atap digambar prosedural dengan warna dari gambarnya. Bus tingkat, van, dan minibus hanya lewat di jalan raya.
- **Tidak dipakai**: modul dinding bata, etalase, dan pintu (gedung terminal terpadu kini dibuat prosedural), sprite orang, prop, dan mobil golf (diganti model 3D supaya tidak terlihat seperti kartu), bus isometrik di panel kiri (saling menumpuk dan perspektifnya berbeda), atap limas, serta elemen UI dan papan bertulisan (teks bahasa Inggris tertanam di gambar). Semuanya tetap tersedia di `assets/potongan/`. Atlas game (`public/aset/atlas.png`, 512×512) hanya berisi sisi bus.

### Save & offline

- Autosave setiap 10 detik waktu main, saat app pause (Capacitor `pause`, atau tab disembunyikan/ditutup di browser), dan setelah penghasilan offline diterapkan.
- Format JSON dengan `schemaVersion`. Decimal disimpan sebagai string `"<mantissa>e<exponent>"` supaya round-trip persis. Blok baru yang belum ada di save lama diisi default, dan perubahan bentuk yang tidak additive memakai `MIGRASI` di `src/sim/save.ts`.
- Save korup tidak membuat crash: error di-log, salinannya disimpan ke `terminal-bus-tycoon/save-korup`, lalu game baru dimulai.
- Offline = pendapatan/detik saat keluar × min(waktu pergi, 4 jam) × 50%, hanya kalau ketiga tahap punya Kepala (tanpa Kepala, terminal hanya berjalan saat game dibuka). Dihitung dari kapasitas, tanpa ritme jam, karena jam terminal berhenti saat game ditutup. Jam yang dimundurkan menghasilkan 0.
