# Bustation: Idle Bus

Situs: [bustation.games](https://bustation.games)

Game tycoon terminal bus dengan tampilan maket 3D. Penumpang melewati **Peron → Loket → Keberangkatan**, dan bus parkir di pangkalan. Bangun jalur, jendela loket, kursi, dan fasilitas di slot denah, rekrut petugas, gandeng mitra PO, atur tarif terminal, dan jaga **laba bersih**: pendapatan dikurangi gaji, perawatan, dan listrik. Terminal tumbuh lewat perluasan dari Tipe C sampai Terpadu.

Stack: TypeScript + Vite · three.js + postprocessing (adegan 3D) · Capacitor 7 (Android) · Vitest.

## Menjalankan di browser

Butuh Node `^20.19` atau `>=22.12`.

```bash
npm install
npm run dev         # buka URL yang muncul; pakai mode HP di DevTools (mis. 390×844)
npm run test        # unit test
npm run build       # typecheck strict + build ke dist/
```

Save tamu disimpan di `localStorage` (kunci `terminal-bus-tycoon/save`; awalan nama lama game sengaja dipertahankan supaya progres pemain tidak hilang). Untuk mulai ulang, hapus kunci itu lewat DevTools → Application → Local Storage.

**Akun & cloud save (web):** pemain bisa masuk dengan Google (tombol akun di pojok adegan). Save lokal tetap dipakai, dan salinannya disinkronkan ke Firestore proyek Firebase `bustation-a4de9` (`saves/{uid}`), paling sering tiap 60 detik dan saat app ke background. Saat login, save tamu dipindah ke akun; logout = mulai sebagai tamu baru. Kalau dua save sama-sama berprogres dan berbeda, pemain selalu ditanya. Kode: `src/app/akun.ts` (logika, dites), `src/platform/firebase.ts`, `src/ui/popup-akun.ts`, `src/ui/popup-pilih-save.ts`. Security rules ada di `firestore.rules`; setelah diubah, tempel ulang di Firebase console → Firestore → Rules. Di APK tombol akun belum tampil (login Google di APK butuh plugin native).

## Rilis web (PWA) & pembaruan in-game

Versi web adalah PWA (`vite-plugin-pwa`): bisa dipasang ke layar utama ("Install app" / "Tambahkan ke layar utama") dan dimainkan offline. Situs resmi `bustation.games` di-host di Cloudflare Pages (project `bustation`): deploy dengan `npm run deploy:web` (build lalu `wrangler pages deploy --branch production`; sekali saja jalankan `npx wrangler login` dulu). Cabang produksi proyek Pages bernama `production`: tanpa `--branch production`, Wrangler memakai nama cabang git (mis. `main`) dan hasilnya hanya pratinjau di `<cabang>.bustation.pages.dev`, bukan bustation.games. Deploy harus lewat Wrangler dari folder ini, bukan unggah lewat dashboard, supaya `functions/` dan `wrangler.toml` ikut:

- `functions/__/[[path]].js` meneruskan `/__/*` ke `bustation-a4de9.firebaseapp.com` sehingga login Google berjalan di domain sendiri (juga di Safari/iPhone);
- `functions/api/peringkat/` adalah API papan peringkat. Binding database D1-nya (`DB` → `bustation-peringkat`) ada di `wrangler.toml`.

Karena `wrangler.toml` ada, pengaturan binding Pages dikelola di file itu, bukan di dashboard. Path aset relatif (`base: './'`). HTTPS wajib (kecuali `localhost`).

**Merilis versi baru:**

1. Naikkan `version` di `package.json` (mis. `0.1.0` → `0.2.0`).
2. Isi `catatan` di `src/config/rilis.config.ts` (±4 butir "Yang baru", tampil di popup).
3. Kalau versi lama tidak boleh dipakai lagi (mis. format save berubah), naikkan `versiMinimal` di file yang sama. Pemain di bawah versi itu mendapat popup wajib tanpa tombol "Nanti".
4. `npm run deploy:web`.

**Yang dilihat pemain:** service worker mengunduh rilis baru di latar. Game memeriksanya saat dibuka, tiap 30 menit selama terbuka, dan setiap kali tab/app kembali terlihat. Setelah rilis baru siap, muncul popup **"Versi baru tersedia"** berisi `0.1.0 → 0.2.0` dan catatan dari `versi.json` rilis baru, dengan tombol **Perbarui sekarang** (progres disimpan dulu, lalu game dimuat ulang ke versi baru) dan **Nanti**. Setelah "Nanti", tombol hijau berpanah dengan titik merah muncul di pojok adegan untuk memperbarui kapan saja. Popup ini menunggu popup lain (mis. "Selama kamu pergi…") ditutup dulu. Kode: `src/app/pembaruan.ts` (logika versi, dites), `src/platform/pembaruan.ts` (service worker), `src/ui/popup-pembaruan.ts`.

**Catatan hosting:** `sw.js` dan `versi.json` jangan di-cache lama oleh server/CDN (bawaan hosting statis umumnya sudah aman). `versi.json` sengaja tidak masuk precache service worker.

**Mencoba alur pembaruan di komputer:** `npm run build && npm run preview`, buka di Chrome, lalu naikkan versi, build lagi, dan kembali ke tab game (atau tunggu pemeriksaan berkala). Di `npm run dev` dan di APK, service worker tidak aktif. Di APK, kode game ikut di dalam APK, jadi pembaruan APK nanti lewat Play Store/unduhan APK baru.

**Ikon aplikasi** (`public/ikon*.png`, `ikon.svg`, `apple-touch-icon.png`) dibuat dari gambar vektor di `tools/ikon/buat-ikon.mjs`: ubah gambarnya lalu jalankan `npm run ikon` (butuh Chrome).

**Pratinjau link** (WhatsApp, Facebook, X): `public/og-image.jpg` 1200×630 (±200 KB; WhatsApp sering tidak menampilkan pratinjau di atas ±300 KB), dipasang lewat meta `og:image` & `twitter:card` di `index.html`. Gambar dibuat dari adegan game dengan `shot.mjs` (UI disembunyikan, judul ditempel); `.jpg` tidak ikut precache PWA. Setelah deploy, cache pratinjau lama di Facebook/WhatsApp bisa disegarkan lewat [Sharing Debugger](https://developers.facebook.com/tools/debug/).

**Kebijakan privasi**: `public/privasi.html` (di situs: `https://bustation.games/privasi`), bahasa Indonesia + versi Inggris, mengacu ke UU No. 27/2022 (PDP). Ditautkan dari menu Akun ("Dengan masuk, kamu menyetujui Kebijakan Privasi") dan lewat `<link rel="privacy-policy">` di `index.html`; `/privasi` dikecualikan dari navigateFallback PWA supaya tidak dijawab halaman game. Isinya harus diperbarui (kedua bahasa, termasuk tanggal berlaku) setiap kali pemrosesan data berubah. Sejak 1 Oktober 2026 kebijakan itu sudah mencakup papan peringkat (bagian 2g) dan iklan berhadiah Google AdSense (bagian 2f: cookie iklan, cara menolak iklan yang dipersonalisasi, persetujuan di Eropa). Kalau penyedia iklan bertambah (AdMob di APK, portal game), perbarui bagian itu lebih dulu. Tautan ini juga dipakai untuk Play Store & portal game.

## Papan peringkat (server)

API kecil di Cloudflare Pages Functions dengan database **Cloudflare D1** `bustation-peringkat` (region APAC, skema di `migrations/`):

| Rute | Siapa | Isi |
|---|---|---|
| `GET /api/peringkat?minggu=YYYY-MM-DD` | publik | 50 teratas minggu ini (atau minggu lalu) + jumlah peserta, di-cache di edge 60 dtk |
| `GET /api/peringkat/saya` | login | skor & peringkat sendiri (dihitung sampai 1.000) |
| `POST /api/peringkat` | login | kirim skor `{minggu, skor, kelas, nama}` |
| `DELETE /api/peringkat` | login | hapus semua skor sendiri (keluar papan / hapus akun) |

- **Login** = header `Authorization: Bearer <ID token Firebase>`. Server memverifikasi token sendiri (`server/token-firebase.ts`): tanda tangan RS256 dengan kunci publik Google yang di-cache, `aud`/`iss` proyek `bustation-a4de9`, kedaluwarsa, dan hanya login Google. Tanpa SDK Admin dan tanpa kunci rahasia di repo.
- **Validasi kiriman** (`validasiKiriman` di `src/app/peringkat.ts`, `server/peringkat.ts`):
  - minggu harus minggu ini menurut jam server (minggu lalu masih diterima 10 menit setelah Senin 00.00);
  - nama dirapikan & disaring;
  - satu kiriman per akun tiap 20 detik;
  - skor tidak pernah turun, dan tidak boleh naik melebihi arus 100 penumpang per detik main (terminal terbesar ±26) × 3× kecepatan sejak kiriman sebelumnya;
  - akun di tabel `larangan` ditolak.
- **Kode**: `functions/api/peringkat/*.ts` (pintu masuk), `server/` (handler, verifikasi token, kueri D1), `migrations/0001_papan_peringkat.sql`. Hanya minggu ini & minggu lalu yang disimpan; yang lebih tua dibuang saat kiriman berikutnya.

**Moderasi** (perintah dari folder ini; `--remote` = database produksi):

```bash
# 10 teratas minggu ini beserta uid (uid tidak pernah tampil di game)
npx wrangler d1 execute bustation-peringkat --remote --command "SELECT uid, nama, kelas, skor FROM papan WHERE minggu = '2026-09-28' ORDER BY skor DESC LIMIT 10"
# blokir akun curang/nama tidak pantas, lalu hapus skornya
npx wrangler d1 execute bustation-peringkat --remote --command "INSERT INTO larangan (uid, alasan, dibuat) VALUES ('UID', 'skor tidak wajar', 0); DELETE FROM papan WHERE uid = 'UID'"
```

**Mencoba di komputer:** `npx wrangler d1 migrations apply bustation-peringkat --local` (sekali), `npm run build`, lalu `npx wrangler pages dev dist --compatibility-date=2026-05-03` (port 8788, D1 lokal di `.wrangler/`). Jalankan `npm run dev` di terminal lain: Vite meneruskan `/api` ke port 8788, dan login Google tetap jalan di `localhost`. `--compatibility-date` diturunkan karena wrangler lokal belum mengenal tanggal proyek (2026-09-28); di produksi tetap memakai tanggal di `wrangler.toml`.

**Mengubah skema:** tambah `migrations/0002_….sql`, coba dengan `--local`, lalu `npx wrangler d1 migrations apply bustation-peringkat --remote` **sebelum** deploy kode yang membutuhkannya.

**Kuota gratis** (cukup untuk ribuan pemain aktif):

| Layanan | Batas | Pemakaian |
|---|---|---|
| D1 baca | 5 juta baris/hari | tiap tampilan papan ±50 baris, tapi di-cache 60 dtk; peringkat sendiri ≤1.000 baris, paling sering tiap 5 menit per pemain |
| D1 tulis | 100 ribu baris/hari | ±1 kiriman per 3 menit per pemain yang ikut |
| Workers | 100 ribu permintaan/hari | semua rute `/api` |

Kalau pemain bertambah banyak, naik ke Workers Paid ($5/bulan).

## Pengelolaan terminal

Konsep **tycoon** (rancangan, keputusan, dan kalibrasinya di `documents/13-rancangan-tycoon.md`): pemain membangun di slot denah, merekrut petugas bergaji, menggandeng mitra PO, dan mengatur tarif terminal; yang dikejar **laba bersih**. Tidak ada upgrade tahap, Kepala, milestone, maupun Renovasi. Panel bawah punya lima tab: **Bangun**, **Petugas**, **PO**, **Terminal**, dan **Target**. Logikanya di `src/sim/state.ts` serta modul murni `src/sim/bangunan.ts`, `petugas.ts`, `tarif.ts`, `operasi.ts` (kapasitas, pasar, kepuasan), `keuangan.ts` (pendapatan, biaya, kas), `mitra.ts`, `level-terminal.ts`, dan `perluasan.ts` (dites di `tests/state.test.ts`, `bangunan.test.ts`, `petugas.test.ts`, `tarif.test.ts`, `operasi.test.ts`, `keuangan.test.ts`, `fitur.test.ts`, `armada.test.ts`, `kelas.test.ts`). Satuan arus: penumpang per jam terminal (1 jam terminal = 60 detik main).

- **Kapasitas & arus** (`hitungOperasi` di `src/sim/operasi.ts`): arus = min(permintaan, peron, loket, keberangkatan, pangkalan). Peron = halte kedatangan × 100 pnp/jam (+25 % untuk halte yang dijaga petugas peron), Loket = jendela loket tiap PO × 50, Keberangkatan = gerbang × 150 (+25 % dengan petugas gerbang), Pangkalan = petak bus × 25 penumpang ÷ 0,75 jam parkir. Modernisasi mengalikan areanya. Kartu "Kapasitas jam sibuk" di tab Bangun menandai area yang paling lambat (merah berdenyut), sama dengan sorotan lantai merah berdenyut di adegan; bila semua calon penumpang terlayani, yang membatasi adalah pasar.
- **Pasar penumpang mutlak** (bukan relatif terhadap kapasitas): calon penumpang tiap jurusan = 45 pnp/jam × peminat jurusan × pengali kelas terminal (Tipe C 1 · B 1,3 · A 1,6 · Terpadu 2) × daya tarik kepuasan (0,6 + 0,8 × kepuasan) × ritme jam × event. Pasar jurusan dibagi ke PO yang melayaninya menurut reputasi (persaingan & kejenuhan), lalu ke kelas busnya, dan berkurang bila biaya layanan mahal. Membangun melebihi pasar hanya menambah biaya; pasar membesar lewat PO baru (jurusan baru), naik kelas, dan kepuasan.
- **Pendapatan** per jam terminal (`keuanganPerJam` di `src/sim/keuangan.ts`): biaya layanan (% harga tiket × penumpang), sewa jendela loket (per hari tiap jendela yang disewa PO), retribusi bus (per bus berangkat; butuh pos retribusi, tanpa petugasnya separuh bus lolos), parkir kendaraan (pengantar ±30 % penumpang; butuh lahan parkir, tanpa juru parkir separuhnya tidak membayar), toilet (±25 % penumpang; butuh toilet), dan sewa kios & toko (per hari tiap unit yang terisi; penyewa mundur bila sewanya di atas nilai wajar menurut keramaian). Parkir & toilet juga dibatasi kapasitas tiap unitnya. Harga tiket ditetapkan PO: Rp 60 rb × nilai jurusan × nilai kelas bus × 1,06^(level PO − 1).
- **Biaya**: gaji petugas, perawatan tiap unit & modernisasi, listrik per jalur (malam ×1,5), dan operasional gedung perluasan. Gaji, perawatan, & listrik dikali kelas terminal (1 · 1,25 · 1,5 · 2).
- **Kas** dalam Rupiah biasa (`number`) dan tidak pernah minus (`majukanKas`): bila habis sementara biaya masih lebih besar, gaji tertunggak dan tiap satu jam terminal petugas yang terakhir direkrut berhenti (manajer paling akhir). HUD memperingatkan lebih dulu ("Kas menipis") bila rata-rata sehari merugi dan kas tinggal kurang dari sehari kerugian. HUD menampilkan kas, **laba hari ini** (merah saat rugi) & penumpang hari ini, arus, kelas, dan kepuasan.
- **Tab Bangun** (aksi `bangun` / `bongkar`; slot, biaya, & perawatan di `EKONOMI.tycoon.bangunan`): jalur bus (halte kedatangan + gerbang keberangkatan; Jalur 2–5 Rp 15 jt, 60 jt, 250 jt, 800 jt, lalu Jalur 6–9 Rp 1,5 M–6 M setelah perluasan tahap 4 & 5), jendela loket (Rp 2 jt, +25 % tiap jendela; langsung disewa PO yang antreannya paling panjang), blok kursi, kios, minimarket & apotek (toko), toilet & musholla, lahan parkir kendaraan, pos retribusi, info petak pangkalan, dan modernisasi. Tiap baris menampilkan jumlah/slot, perawatan per hari, dan bila slot penuh, tahap perluasan yang menambahnya. **Bongkar** (dua ketukan) mengembalikan 30 % harga unit; jalur permanen, dan hanya jendela loket kosong yang bisa dibongkar. Petugas yang melebihi batas barunya ikut keluar.
- **Tab Petugas** (aksi `rekrut` / `berhentikan`, `src/sim/petugas.ts`): petugas peron & gerbang (satu per jalur), petugas kebersihan (sampai 2 × jalur + 2), satpam (sampai dua per jalur), juru parkir (satu per lahan parkir), petugas toilet (satu per toilet), petugas retribusi (satu per pos), **Manajer Operasional** (terminal tetap jalan saat game ditutup), dan **Manajer Kemitraan** (menyewakan jendela kosong & memperpanjang kontrak otomatis). Rekrut tanpa biaya sekali bayar; gaji per posisi per hari (satu posisi = tiga shift). State menyimpan urutan rekrut, jadi yang terakhir direkrut berhenti lebih dulu.
- **Kepuasan penumpang** (pil di HUD, diketuk untuk rincian; `src/ui/popup-kepuasan.ts`): dinilai dari keadaan jam sibuk (tidak naik-turun mengikuti jam), enam komponen: kelancaran 30 % (arus ÷ permintaan: 0 di ≤ 50 %, penuh di ≥ 95 %), kenyamanan 20 % (kursi untuk penumpang yang menunggu, papan jadwal digital), kebersihan 20 % (satu petugas kebersihan per 150 pnp/jam; toilet tanpa petugasnya cepat kotor), keamanan 10 % (satu satpam per jalur), fasilitas 10 % (toilet, kios & toko, lahan parkir menurut keramaian), harga 10 % (biaya layanan, tarif parkir & toilet). Popup memberi saran per komponen. Kepuasan menambah calon penumpang dan reputasi PO; PO premium butuh kepuasan (Telolet Jaya 65 %, Sultan Garasi 80 %).
- **Tarif terminal** (tab Terminal; aksi `aturTarif` & `saranTarif`, `src/sim/tarif.ts`): biaya layanan 10 % harga tiket (0–25 %; barisnya menampilkan rupiahnya per penumpang dari rata-rata harga tiket yang berangkat sekarang, `hargaTiketRata` di `src/ui/model.ts`), sewa jendela loket Rp 250 rb/hari, retribusi Rp 20 rb/bus, parkir Rp 5 rb, toilet Rp 2 rb, sewa kios & toko Rp 300 rb/hari (bawaan). Tarif lebih tinggi menurunkan permintaan, pemakai parkir & toilet, okupansi kios, atau kepuasan mitra PO. Tombol **Saran** memilih tarif dengan laba sehari terbaik selama kepuasan mitra semua PO tetap ≥ 50 %. Hadiah, target, dan laba offline memakai rata-rata sehari dengan tarif bawaan (laba offline tidak pernah melebihi hasil tarif bawaan), jadi tarif ekstrem sesaat tidak menggelembungkan hadiah.
- **Laporan keuangan** (tab Terminal): pendapatan per sumber & biaya per pos hari ini dan kemarin (buku harian di state), laba bersih, penumpang, dan laba rata-rata sehari dengan tarif sekarang.
- **Mitra PO** (tab PO): dua puluh perusahaan otobus fiktif bertingkat **Lokal / Regional / Nasional / Premium**. Tingkat menentukan kelas bus tertinggi (Lokal sampai Eksekutif, Regional sampai Sleeper, Nasional & Premium sampai Double Decker), jendela bawaan (2/3/4/4), dan reputasi awal. Game baru dimulai dengan **PO Ondel-Ondel** (Jakarta) yang menyewa satu-satunya jendela loket.
  - **Jurusan**: tiap PO melayani tiga kota; yang kedua terbuka di PO Lv 6, yang ketiga di Lv 12, dan rute antarpulau juga butuh kelas terminalnya. PO berbeda boleh melayani jurusan yang sama dan bersaing di sana.
  - **Kelas bus** terbuka seiring level PO: Patas AC Lv 3, Eksekutif Lv 6, Sleeper Lv 10 (butuh Terminal Tipe B), Double Decker Lv 15 (Tipe A), sebatas tingkat PO. Kartu PO menampilkan harga tiket Ekonomi tiap jurusan (informasi; ditetapkan PO). Penghargaan "Armada Lengkap" saat kelima kelas beroperasi.
  - **Level PO** dari bus yang berangkat (25 penumpang PO itu = 1 XP); XP kumulatif = 15 × (L − 1)³. XP juga bertambah saat game ditutup (× 60 %, bila ada Manajer Operasional).
  - **Jendela loket**: tombol "+ Jendela" di kartu PO membangun jendela untuk PO itu (gratis bila ada jendela kosong). Kartu menampilkan kapasitas jendelanya dibanding peminat jam sibuk PO itu, bagian penumpangnya, dan **kepuasan mitra**.
  - **Kepuasan mitra** (0–100 %): tarif sewa jendela & retribusi, bus yang penuh, antrean jendela yang pendek, dan kepuasan penumpang. Kontrak hanya diperpanjang (gratis) bila ≥ 50 %, termasuk oleh Manajer Kemitraan; PO baru menolak bergabung bila perkiraannya di bawah itu.
  - **Mendaftarkan PO**: butuh slot (level terminal), biaya daftar (Rp 3 jt sampai Rp 10 M), kelas terminal, dan jendela: jendela kosong dipakai lebih dulu, sisanya dibangun PO sendiri di slot kosong (tanpa jendela kosong maupun slot, PO tidak bisa bergabung). PO hadiah gratis: Juara Kelas (Tipe B), Juara Umum (Tipe A), dan PO event.
  - **Kontrak** 7 hari terminal (PO hadiah 14), hanya berkurang saat main. Kontrak habis → PO keluar, jendelanya kosong, XP & reputasinya disimpan di riwayat lalu dilanjutkan bila didaftarkan lagi. PO terakhir diperpanjang gratis, jadi terminal tidak pernah tanpa PO. **Putus** gratis lewat dua ketukan, tapi reputasi PO −10 dan baru bisa didaftarkan lagi 3 hari terminal kemudian.
  - **Reputasi** (0–100) bergerak pelan menuju 25 + 50 × kepuasan + 20 × banyaknya kelas ÷ 5 (harga tiket di tangan PO, selalu normal), konstanta waktu 20 menit main. Reputasi menentukan bagian pasar PO di jurusannya.
- **Jurusan di adegan**: bus hanya melayani jurusan yang dilayani PO terdaftar (`maskJurusanState` di `src/game/laju.ts`, bitmask karena jurusan tiap PO tidak harus urut): pengumuman dan label keberangkatan mengikutinya. Tiap bus terminal yang baru muncul milik salah satu PO terdaftar, sebanding bagian penumpangnya (`pilihPoBus` di `src/game/dunia-visual.ts`, tetap untuk id bus yang sama): livery & kelas busnya dari PO itu, dan jurusannya salah satu jurusan PO itu. Tiap kelompok parkir punya satu dari tiga keadaan (`keadaanKelompokParkir` di `src/game/perluasan-adegan.ts`; 2 kelompok dibangun di terminal awal, 4 setelah perluasan tahap 2): **belum dibangun** (papan pulau "SEGERA DIBUKA" kelabu, mulut petaknya dibarikade oranye oleh `src/game/pembangunan3d.ts`, tidak dipakai), **berjurusan** (ada jurusannya yang dilayani; papan berwarna kelompok dengan nama jurusannya), atau **parkir tambahan** (sudah dibangun tapi jurusannya belum dilayani; papan putih "PARKIR TAMBAHAN" dengan baris "BELUM ADA PO …", tanpa barikade). Bus mencari petak berurutan: kelompok jurusan PO pemiliknya, lalu parkir tambahan, lalu kelompok jurusan lain; bila semua penuh, bus langsung keluar terminal. Papan pulau dibangun sekali saat pertama dibutuhkan (`src/game/papan-jurusan3d.ts`).
- **Jendela loket per PO** (`src/game/perluasan-adegan.ts`, murni dan dites): tiap jendela loket yang disewa PO tampil di aula, sebatas jendela yang muat di adegan (4 di terminal awal, 6 setelah perluasan tahap 1, 8 setelah tahap 2). Jendela dibuka mulai dari yang tepat di depan kepala antrean (`URUTAN_LOKET`: LOKET 4, 5, 3, 6, 2, 7, 1, 8), lalu dibagi ke PO menurut loketnya (`jendelaPo`: tiap PO satu dulu, sisanya ke PO dengan jendela sewaan per jendela tampil terbanyak); jendela tiap PO berderet dari barat ke timur dan papan di atasnya memakai nama & warna livery PO itu. Jendela yang belum dipakai bertuliskan "SEGERA DIBUKA", tertutup rolling door, tanpa petugas, dan tidak melayani pembeli (`loketBuka` di `src/game/kehidupan-malam.ts`; malam hari separuhnya ikut tutup). Selama baru ≤2 jendela yang buka tiap jendela menampung 5 pembeli, jadi jendela yang sedikit tidak tampak sebagai hambatan palsu; arus calon penumpang di adegan dibatasi jendela yang buka (`batasArusLoket`).
- **Rute antarpulau** (`feri` & `kelasTerminal` di `EKONOMI.jurusan`): delapan jurusan yang busnya ikut menyeberang dengan kapal feri, dilayani PO tertentu (mis. Siger Sakti–Lampung, Kecak Laju–Mataram, Rinjani Indah, Rumah Gadang, Danau Toba, Kopi Gayo) dan baru dilayani setelah terminal mencapai kelasnya: Lampung & Palembang (Tipe B), Mataram, Jambi, Padang (Tipe A), Bima, Medan, Banda Aceh (Terpadu). Penyeberangannya Merak–Bakauheni untuk Sumatra, Padangbai–Lembar ke Lombok, Kayangan–Pototano ke Sumbawa; kartu PO menandainya dengan ikon kapal. Notifikasi "⛴ Rute antarpulau … dibuka oleh PO …". Di adegan: rute antarpulau berangkat dari keempat kelompok parkir (dua per kelompok, `KELOMPOK_PARKIR.antarpulau`), papan pulau mendapat baris kedua berikon kapal berisi kota antarpulau yang dilayani, label & pengumuman keberangkatan menyebut kotanya, dan rambu hijau "PELABUHAN MERAK ← / → PELABUHAN PADANGBAI" muncul di median jalan raya dekat pintu keluar bus (`src/game/antarpulau3d.ts`, pelabuhan per penyeberangan di `src/game/antarpulau.ts`, murni dan dites). Rute antarpulau dijual di jendela loket yang sudah ada (tetap delapan). Penghargaan "Penghubung Jawa–Bali" (semua jurusan sampai Denpasar dilayani sekaligus), "Menyeberang Pulau" (rute antarpulau pertama), dan "Lintas Nusantara" (semua rute sampai Banda Aceh).
- **Level & kelas terminal** (kartu teratas tab Terminal, pil "Tipe C · Lv 1" di HUD; `src/sim/level-terminal.ts`): XP = penumpang yang diberangkatkan, termasuk saat game ditutup (× 60 %, bila ada Manajer Operasional). XP kumulatif = 50 × (L − 1)^2,75. Kelas mengikuti level dan tidak pernah turun: Tipe C Lv 1–9, Tipe B 10–19, Tipe A 20–29, Terpadu ★1 30–39, ★2 40–49, dan seterusnya. Level tidak memberi bonus pendapatan: ia membuka slot PO (2 → 3 di Lv 3 → 4 di Lv 6 → 5 di Lv 10 → … 12 di Lv 60; lebih dari 8 butuh perluasan tahap 4), kelas, dan perluasan. Kelas yang lebih tinggi memperbesar pasar tapi menaikkan gaji, perawatan, & listrik. Penghargaan "Naik Kelas", "Terminal Tipe A", & "Terminal Terpadu".
- **Perluasan terminal** (tab Terminal; `src/sim/perluasan.ts`): lima tahap permanen (Terminal Lv 3, 6, 10, 20, 30; Rp 20 jt / 80 jt / 250 jt / 800 jt / 3 M). Proyeknya sehari terminal dan tetap berjalan saat game ditutup. Setelah diresmikan, slot bangunan bertambah (jendela loket, petak bus, jalur, kursi, toko, toilet, lahan parkir; tabelnya di `EKONOMI.tycoon.bangunan` & `petakBus`) dan gedungnya berbiaya operasional per hari (Rp 0,5 jt / 2 jt / 6 jt / 20 jt / 60 jt, menumpuk). Di adegan, tahap 1 menambah 2 jendela loket di kedua ujung deretan, dan tahap 2 menambah 2 jendela lagi serta kelompok parkir 3–4. Selama proyek berjalan (`LOKASI_PROYEK` di `src/game/perluasan-adegan.ts`, digambar `src/game/proyek3d.ts`) lokasinya dipagari seng berpapan "PROYEK PERLUASAN TERMINAL · TAHAP n", ada crane menara yang lengannya berputar pelan, tumpukan bata/pasir/besi, pekerja berompi yang mondar-mandir, perancah keliling sayap barat (tahap 3), dan papan "SEDANG DIBANGUN" di jendela loket yang sedang dibangun. Saat diresmikan, kembang api meledak di atas lokasinya (`src/game/kembang-api.ts`, murni dan dites; waktu nyata, tidak saat memuat save). Pagar proyek pangkalan tidak menghalangi bus di kelompok yang sudah dipakai (dicek di `tests/perluasan-adegan.test.ts`). Tampilan 3D bangunan bertingkat (tahap 3–5) menyusul (rancangan di `documents/12-rancangan-ekonomi-po.md` bagian 8).
- **Event musiman** (kalender murni di `src/sim/event.ts`, logika di bagian Event musiman `src/sim/state.ts`, angka di `EKONOMI.event`): mengikuti tanggal nyata WIB — **Mudik Lebaran** H−10 sampai H+7 Idul Fitri (tabel perkiraan 2025–2030, tahun lain dihitung per tahun hijriah), **HUT RI** 10–20 Agustus, **Libur Natal & Tahun Baru** 20 Desember – 5 Januari. Selama event calon penumpang dikali (`pengaliPasar`: Mudik ×1,5, Nataru ×1,3, HUT RI ×1,17), jadi kapasitas & petugas cadangan terasa gunanya; ada tiga tahap target "berangkatkan N penumpang" (N = arus rata-rata saat event dimulai × 20 menit / 1 jam / 3 jam main) dengan hadiah 5/15/30 menit laba; tahap terakhir membuka mitra PO eksklusif yang bisa didaftarkan gratis (Mudik Ceria, Merah Putih, Kembang Api). Progres & hadiah dicatat per edisi (mis. `mudikLebaran-2027`): dibuka ulang di tengah event melanjutkan progres, hadiah yang sudah tercapai tetap bisa diklaim setelah event selesai, edisi berikutnya mulai dari nol. Sesi (`src/app/sesi.ts`) mencocokkan event dengan jam dinding saat mulai, saat kembali dari background, dan tiap 30 detik. Tampilan: kartu event di atas tab Target (sisa waktu, tahap, kemajuan, klaim), pil event di HUD, notifikasi saat event dimulai & tahap selesai; di adegan spanduk ucapan di gapura, ketupat (Mudik), bendera merah-putih di median (HUT RI), lampu warna-warni di gapura (Nataru), dan terminal ramai sepanjang hari (`src/game/event3d.ts`). **Mencoba di server dev:** `http://localhost:5173/?event=mudikLebaran` (atau `hutRi`, `nataru`) memaksa event edisi uji; parameter ini diabaikan di build produksi supaya hadiah tidak bisa dicurangi.
- **Modernisasi** (bagian bawah tab Bangun; sekali beli Rp 10 jt–400 jt, perawatan ±0,1 % harganya per hari, menambah kapasitas satu area, dua tingkat per area): Marka & rambu halte → Sistem pengatur bus (Peron), Mesin tiket mandiri → Tiket online (Loket), Papan jadwal digital → Gate e-boarding otomatis (Keberangkatan). Tingkat kedua butuh tingkat pertama. Papan jadwal digital juga menambah kenyamanan. Di 3D (`src/game/modernisasi3d.ts`) perlengkapannya muncul setelah dibeli: rambu bernomor A1–A5 & marka di peron kedatangan, petugas berompi, mesin tiket di plaza, papan E-TIKET di depan pintu masuk, papan jadwal digital & gate e-boarding di ruang tunggu.
- **Nama terminal** (tombol ✎ di kartu level tab Terminal; `src/sim/profil.ts`, popup `src/ui/popup-nama.ts`, dites di `tests/profil.test.ts`): pemain boleh menamai terminalnya (maks. 18 huruf; hanya huruf, angka, spasi, `.`, `'`, `-`; awalan "Terminal" dibuang karena sudah tertulis). Nama tampil di papan gapura ("TERMINAL SUKAMAJU" dengan tipe terminal di baris kedua, warna papan mengikuti kelas; `src/game/kelas3d.ts`), judul kartu level terminal, dan keterangan foto yang dibagikan. Kosong = papan bawaan "TERMINAL TIPE C". Disimpan di blok `profil`. Analitik hanya mencatat ada/tidaknya nama, **tidak pernah namanya**.
- **Target harian**: berganti tiap hari terminal, bergantian "berangkatkan N penumpang" (N = setengah arus rata-rata sehari) dan "raih laba bersih Rp N hari ini" (setengah laba rata-rata sehari dengan tarif bawaan). Selesai → klaim hadiah 2 menit laba.
- **Hadiah "N menit laba"** (target, tantangan, event, penghargaan, Bus Emas): N × laba rata-rata per jam terminal sepanjang hari biasa dengan tarif bawaan (`hadiahMenit` & `acuanHarian` di `src/sim/state.ts`), paling sedikit N × Rp 200 rb supaya tetap terasa saat rugi.
- **Tantangan mingguan** (kartu di tab Target; minggu & pilihan jenis murni di `src/sim/tantangan.ts`, angka di `EKONOMI.tantangan`, dites di `tests/tantangan.test.ts`): mengikuti **jam nyata WIB**, minggu baru tiap **Senin 00.00 WIB**. Tiap minggu tiga dari empat jenis diundi dari tanggal minggunya, jadi semua pemain mendapat jenis yang sama:
  - berangkatkan N penumpang (arus rata-rata saat minggu dimulai × 2 jam main);
  - kumpulkan laba bersih Rp N (laba rata-rata × 3 jam main);
  - bangun 15 unit atau modernisasi;
  - jaga kepuasan ≥ 75 % selama 60 menit main.

  Penumpang & laba hanya dihitung dari main aktif. Hadiah tiap tantangan 15 menit laba. Hadiah yang selesai tapi lupa diklaim dikirim otomatis saat minggu berganti. Sesi mencocokkan minggu dengan jam dinding saat mulai, saat kembali dari background, dan tiap 30 detik (`perbaruiJamNyata`).
- **Rekor terminal** (kartu di bawah tantangan): penumpang & laba hari ini, rekor penumpang & laba terbanyak sehari, dan arus tertinggi (`RekorState` di `src/sim/state.ts`). Hari yang lewat dibandingkan dengan rekor saat hari berganti; rekor penumpang baru memunculkan notifikasi "🏅 Rekor baru".
- **Papan peringkat mingguan** (kartu di bawah tantangan, hanya web; server di bagian "Papan peringkat (server)"):
  - Skornya **penumpang minggu ini** (`tantangan.penumpang`): dihitung dari main aktif, reset Senin 00.00 WIB.
  - Kartu menampilkan penumpangmu minggu ini dan, kalau ikut, "Peringkatmu #N dari M terminal". Tombol **Lihat papan** membuka popup 50 teratas (medali 🥇🥈🥉, tipe terminal, skor lengkap sampai 10 juta), tab **Minggu lalu** untuk hasil akhir, dan baris sendiri yang disorot (di luar 50 besar ditambahkan di bawah).
  - Tamu hanya bisa melihat, lalu diajak masuk dengan Google. Pemain yang login harus **menyetujui** dulu bahwa nama terminal, tipe, dan skornya tampil publik (`profil.ikutPeringkat` di save). Nama kosong → diminta mengisi nama dulu; nama kasar/cabul ditolak (`namaLayakPublik`).
  - Skor dikirim otomatis paling sering tiap 3 menit, segera saat nama/kelas berubah, dan saat game ke latar (`PengirimSkor`). Gangguan jaringan dicoba lagi dengan jeda makin panjang. Galat yang perlu tindakan pemain tampil di kartu & popup (nama ditolak, jam perangkat salah, sesi login berakhir).
  - **Keluar dari papan** (dengan konfirmasi) menghapus skornya di server dulu. **Hapus akun** juga menghapus skor papan sebelum cloud save.
  - Tidak ada hadiah gameplay dari peringkat, jadi curang hanya merusak gengsi, bukan ekonomi.
  - Kode: `src/app/peringkat.ts` (kontrak API, saringan nama, validasi; dipakai game **dan** server), `src/app/layanan-peringkat.ts`, `src/platform/peringkat.ts`, `src/ui/peringkat.ts`; dites di `tests/peringkat.test.ts` & `tests/peringkat-server.test.ts`.
- **Penghargaan**: 20 pencapaian (petugas pertama, fasilitas pertama, target harian pertama, Manajer Operasional, sepekan beroperasi, lima jalur, jurusan Jawa–Bali, Tipe B, tujuh hari tanpa rugi, 100 rb penumpang, rute antarpulau pertama, fasilitas lengkap, semua modernisasi, kas Rp 1 M, Tipe A, armada lengkap, aula loket penuh, Terpadu, sejuta penumpang, Lintas Nusantara), masing-masing hadiah 3 menit laba saat diklaim. Tercatat otomatis tiap tick; jumlah hadiah yang siap diklaim tampil sebagai lencana merah di tab Target.
- **Notifikasi** (`src/ui/notifikasi.ts`, murni): satu pesan terpenting tiap pembaruan; petugas yang berhenti karena kas habis & "Kas menipis" didahulukan, lalu mis. event, kelas & level terminal, perluasan diresmikan, PO bergabung / keluar karena kontrak habis / naik level, kontrak tinggal sehari, rute antarpulau, slot PO baru, kelas bus baru, jalur, penghargaan, tantangan, rekor, dan target harian.

## Hadiah iklan berhadiah

Pemain **memilih sendiri** menonton iklan untuk hadiah; tidak ada iklan paksa dan tidak ada fitur gratis yang dikunci. Angkanya di `EKONOMI.hadiah` (`src/config/economy.config.ts`), logikanya di bagian Hadiah `src/sim/state.ts` (murni, dites di `tests/hadiah.test.ts`):

- **Ambil 2×** di popup "Selama kamu pergi…": laba offline laporan itu diberikan sekali lagi bila positif (sekali per laporan; tidak disimpan, hanya ditawarkan di popup).
- **Boost pendapatan 2×** (tombol ⚡ di kolom kontrol, lencana sisa waktu): pendapatan 2× (biaya tetap), +30 menit waktu main per iklan, ditumpuk sampai 4 jam. Tetap berjalan (dan habis) saat game ditutup: pendapatan offline yang ter-boost ikut 2×. HUD menandai laba hari ini dengan ⚡2×.
- **Bus Emas**: tiap 5–10 menit waktu main (diundi dari benih game) muncul penanda "Bus Emas!" dan bus berwarna emas melintas di jalan raya. Selama 60 detik bisa diketuk: tonton iklan untuk bonus 10 menit laba. Setelah diketuk, bus menunggu selama pemain menonton; "Nanti" = bus pergi dan dijadwalkan lagi.
- **Klaim 2×** target harian & penghargaan (tombol emas di tab Target).

Penyedia iklannya terpisah (`src/app/iklan.ts` kontraknya, `src/platform/iklan.ts` penyedianya), jadi bisa diganti tanpa mengubah mekanik.

**Google H5 Games Ads (web)** sudah terpasang, tapi **nonaktif** selama `ID_PENERBIT_ADSENSE` di `src/config/iklan.config.ts` kosong:

- Alurnya mengikuti Ad Placement API (`src/app/iklan-h5.ts`, dites di `tests/iklan-h5.test.ts`):
  - game meminta jeda `reward` lebih dulu. Tombol hadiah (⚡ boost, Bus Emas, klaim 2×) baru muncul setelah Google memanggil `beforeReward` (ada iklan siap);
  - ketukan pemain memanggil `showAdFn` langsung. Hadiah hanya diberikan pada `adViewed`, sedangkan `adDismissed` berarti tanpa hadiah. Suara game dibisukan selama iklan;
  - tanpa iklan (belum disetujui, stok kosong, dibatasi frekuensi, atau skrip diblokir ad blocker), tombol tetap tersembunyi dan permintaan diulang dengan jeda makin panjang (15 dtk → 5 menit).
- Sudah dicoba dengan iklan uji Google: iklan tayang, lalu boost 2× diberikan setelah iklan selesai.
- **Mengaktifkan**:
  1. Daftar Google AdSense, lalu isi ID penerbit (`ca-pub-` + 16 angka) di `iklan.config.ts` dan `npm run deploy:web`. Build otomatis memasang meta `google-adsense-account` di `index.html` dan `/ads.txt`.
  2. Tunggu situs disetujui, lalu ajukan H5 Games Ads untuk bustation.games.
  3. Di AdSense → *Privasi & pesan*, aktifkan pesan persetujuan untuk Eropa. Kebijakan privasi bagian 2f sudah menjanjikannya.
  4. Coba di `https://bustation.games/?iklan=uji` (iklan uji Google, tanpa pendapatan).
- ID boleh diisi sebelum H5 Games Ads disetujui: selama Google belum memberi iklan, tombol hadiah tidak muncul.
- APK nanti memakai AdMob lewat plugin native; di APK iklan selalu nonaktif dulu.

**Iklan contoh**: di `npm run dev` dan di situs dengan **`?iklan=contoh`** (mis. `https://bustation.games/?iklan=contoh`) muncul layar hitung mundur 5 detik (bisa dilewati tanpa hadiah) untuk mencoba mekanik hadiah tanpa jaringan iklan. Tanpa ID penerbit, pemain biasa & APK tidak melihat tombol hadiah dan Bus Emas tidak ditampilkan.

## Tutorial & analitik

- **Tutorial terpandu** untuk game yang benar-benar baru (`src/app/tutorial.ts`, murni dan dites; tampilannya `src/ui/tutorial.ts`): sambutan singkat, lalu empat langkah (terminal sudah berjalan sendiri sejak awal): (1) bangun jendela loket di tab Bangun (di awal Loket yang paling lambat, lantainya berkedip merah; jendelanya disewa PO yang antreannya paling panjang), (2) daftarkan PO kedua di tab PO (yang termurah di antara yang syaratnya terpenuhi, biasanya PO Peuyeum Kilat; PO tersedia diurutkan termurah dulu, dan daftarnya bergulir sampai tombolnya terlihat), (3) rekrut petugas peron di tab Petugas (kini Peron yang paling lambat; tanpa biaya sekali bayar, gajinya per hari), (4) bangun Jalur 2 di tab Bangun (tujuan pertama yang terlihat di adegan: bus tidak lagi antre di jalan raya). Modal awal Rp 25 jt cukup untuk keempatnya. Diakhiri gelembung penutup berisi saran fasilitas, Manajer Operasional, & tips klakson telolet. Tidak pernah menghalangi: pemain boleh melakukan apa saja, dan tiap langkah selesai sendiri begitu syaratnya terpenuhi (urutan bebas). Gelembung ada di bawah adegan dan tombol yang dituju berkedip kuning; bila tombolnya tersembunyi (tab lain terbuka atau panel diringkas), yang disorot tab/tombol buka panelnya. Kemajuan kas ditampilkan ("Kas Rp 1,2 jt / Rp 2 jt"). "Lewati" kapan saja. Status disimpan per perangkat (`terminal-bus-tycoon/tutorial`: aktif/selesai/dilewati); save lama yang sudah berjalan tidak mendapat tutorial.
- **Analitik** (Google Analytics 4 lewat gtag.js, tanpa SDK Firebase supaya pemain tamu tidak mengunduh Firebase): ID pengukuran `G-L03D1C21GC` (proyek Firebase bustation-a4de9) di `src/config/analitik.config.ts`; kosongkan `ID_GA4` untuk mematikannya. Hanya di web (bukan APK), tanpa sinyal Google & personalisasi iklan. Peristiwa (`src/app/analitik.ts`, murni dan dites): `mulai_game` (save baru/dimuat, tamu/login), `tutorial_begin` / `tutorial_langkah` / `tutorial_complete` / `tutorial_lewati`, `bangun` & `bongkar` (bangunan & jumlahnya), `rekrut` (peran & jumlahnya) & `berhentikan`, `atur_tarif` & `saran_tarif` (tarifnya saja, sekali per sesi tiap tarif), `beli_teknologi`, `daftar_po` (PO & jumlah PO terdaftar), `putus_po`, `perpanjang_po`, `po_keluar` (kontrak habis), `mulai_perluasan` (tahap), `klaim_event` (edisi & tahap), `klaim_target`, `klaim_penghargaan`, `iklan_hadiah` (tempat & hasil), `hadiah_boost` / `hadiah_bus_emas` / `hadiah_offline_2x`, `login`, `telolet` (sekali per sesi), `foto_terminal`, `share` (peristiwa bawaan GA4: `method` web_share/unduh), `mode_sinema` (waktu & cuaca), `adegan_siap` (detik sampai 3D siap) / `adegan_gagal`, `nama_terminal` (hanya `ada` true/false, bukan namanya), `klaim_tantangan` (jenis & minggu), `peringkat_buka` (`akun` tamu/login, `ikut`), `peringkat_ikut` / `peringkat_keluar` (tanpa nama terminal).   - `exception` (peristiwa bawaan GA4): error JavaScript & promise yang tidak tertangani, plus kegagalan 3D. Isinya `description` (pesan ≤ 100 karakter + `@berkas:baris`) dan `fatal`. Tiap pesan dikirim sekali, paling banyak 10 per sesi;
  - `ringkasan_sesi`: dikirim saat game masuk background (tab ditutup/disembunyikan, aplikasi dijeda), lalu dihitung ulang saat kembali. Isinya `detik` (nyata), `detik_main`, `penumpang`, `pendapatan_juta` & `laba_juta`, `bangun` (unit & modernisasi yang dibangun), `kas_juta`, `kelas` & `level_terminal`, `jalur`, `jurusan` (yang dilayani PO), `po` (PO terdaftar), `petugas`, `kepuasan` (%).

  Retensi (kembali besok / minggu depan) dihitung GA4 sendiri. Kebijakan privasi (`public/privasi.html`) menyebut ringkasan sesi & laporan error. Di `npm run dev` peristiwa hanya ditulis ke konsol (`console.debug`, level Verbose); `?analitik=debug` di situs mengirimnya ke DebugView GA4 sekaligus menulis ke konsol.

## Kehidupan terminal sehari-hari

Murni tampilan; logika jam & rute di `src/game/kehidupan-malam.ts` dan `src/game/jadwal.ts` (dites di `tests/kehidupan.test.ts`).

- **Jam buka**: minimarket di aula buka 24 jam; apotek buka 07–22, kios ruang tunggu (kopi, roti, oleh-oleh) 05–22.30. Saat tutup, rolling door seng turun dan penjaganya pulang (`src/game/malam3d.ts`). Tiap kios & toko baru buka setelah unitnya dibangun (kios ruang tunggu urut KOPI, ROTI & KUE, OLEH-OLEH; toko aula urut minimarket lalu apotek): yang belum dibangun tertutup rolling door sepanjang hari, tanpa penjaga, dan tidak didatangi penumpang. Toilet & musholla di sayap barat baru didatangi setelah toilet dibangun (`fasilitas` di `LajuVisual`, dari `fasilitasAdegan` di `src/game/fasilitas-adegan.ts`). Pukul 22–05 separuh jendela loket yang buka ikut tutup, paling sedikit dua tetap buka (rolling door bertulisan TUTUP, tanpa petugas); pembeli hanya dipanggil ke jendela yang buka.
- **Petugas di adegan** (`stafAdegan` di `src/game/fasilitas-adegan.ts`, posisi di `tata-letak.ts`): yang terlihat sebanyak yang direkrut. Petugas peron berdiri di tepi peron tiap halte kedatangan & petugas gerbang di samping gerbang ruang tunggu (urut jalur); satpam mengisi pos urut `POS_SATPAM` (pos luar di samping bordes, di balik pintu masuk aula, ujung barat peron keberangkatan, ujung barat peron kedatangan); petugas kebersihan berseragam menyapu dengan sapu ijuk, siang & malam, di rute urut `RUTE_SAPU` (aula, ruang tunggu, peron kedatangan, plaza; yang di plaza berteduh saat hujan deras). Juru parkir, petugas toilet, dan petugas retribusi hadir bila bangunannya ada **dan** petugasnya direkrut. Petugas di luar pos & rute yang ada bertugas di luar pandangan.
- **Malam**: pukul 19–05.30 satpam pertama berkeliling plaza menyusuri pagar (siang berjaga di posnya).
- **Luar pagar** (`src/game/luar3d.ts`): pangkalan ojek di mulut gang gerbang KELUAR (gubuk beratap dengan bangku & papan "PANGKALAN OJEK", tiga ojek menunggu penumpang turun; di atas pukul 23 tinggal satu), pengemudi ojol berjaket hijau di mulut gang gerbang MASUK (jumlahnya ikut keramaian), dan dua pedagang asongan dengan kotak dagangan mondar-mandir di dalam kedua gerbang pagar (06–22, berpayung saat hujan).
- **Papan jadwal** (`src/game/papan-jadwal3d.ts`): papan besar di aula dan papan jadwal digital di ruang tunggu menampilkan jam terminal dan bus yang benar-benar ada: jam berangkat ditetapkan sekali saat bus diparkir (perkiraan sisa cuci + menunggu jadwal + ke halte + ngetem, dibulatkan ke atas per 5 menit), lalu kolom JALUR dan STATUS mengikuti keadaan bus: PERSIAPAN, SIAP (menuju jalur), NAIK, BERANGKAT, atau TERLAMBAT bila jamnya lewat sebelum bus mulai memuat.
- **Pengantar** (`src/game/rombongan.ts`): ±5 % penumpang diantar sampai gerbang keberangkatan (ikut antre, duduk di sebelahnya di ruang tunggu). Begitu penumpangnya keluar gerbang, pengantar berhenti di dalam ruang tunggu di samping gerbang dan melambaikan tangan sampai busnya berangkat, lalu pulang lewat aula dan gerbang pagar MASUK.

## Jam terminal, hari, siang–malam, cuaca

- **Jam 24 jam & hari Senin–Minggu** (`src/sim/waktu.ts`): diturunkan dari waktu main aktif (`statistik.waktuMainDetik`), jadi ikut tersimpan di save tanpa mengubah format save. Jam berhenti saat game ditutup. Game baru mulai **Senin 06:00**. HUD kanan atas menampilkan ikon matahari/bulan, nama hari (Minggu berwarna merah), dan jam `HH:MM`.
- **Kecepatan waktu 1× / 2× / 3×**: tombol di bawah jam HUD (atau tombol keyboard 1, 2, 3); pilihannya disimpan (`terminal-bus-tycoon/kecepatan`). Seluruh permainan berjalan sekian kali lebih cepat: jam terminal, bus, orang, lalu lintas, cuaca, dan simulasi ekonomi (pendapatan per detik nyata ikut ×2/×3). Laba offline tetap dihitung dari waktu nyata, autosave tetap tiap 10 detik nyata, dan efek visual yang terasa janggal bila dipercepat (tetes hujan, kedip lampu, kibar bendera, kamera, jeda pengumuman) tetap waktu nyata. Simulasi keramaian dijalankan dalam langkah ≤ 0,05 detik main supaya tetap stabil. Pilihan di `PILIHAN_KECEPATAN` (`src/config/waktu.config.ts`).
- **Skala waktu** di `src/config/waktu.config.ts`: `detikPerJam` (bawaan 60, jadi satu hari terminal = 24 menit nyata dan sepekan ≈ 2,8 jam), `jamAwal`, `jamTerbit`, `jamTerbenam`. Selain `detikPerJam` (yang ikut menentukan lamanya jam sepi, lihat ritme), semuanya murni tampilan.
- **Siang–malam** (`src/game/langit.ts`, murni dan dites): titik kunci suasana dari fajar, pagi, siang, sore, senja, sampai malam diinterpolasi halus. Matahari terbit di timur dan terbenam di barat. Di malam hari cahaya utama berganti ke bulan kebiruan. Pergantian matahari ↔ bulan terjadi saat cahaya padam, jadi bayangan tidak melompat. Tingkat malam menyalakan lampu jalan (dengan genangan cahaya di tanah, `src/game/cahaya3d.ts`), jendela gedung kota, lantai & kaca aula terminal, papan nama, papan jadwal, serta lampu depan & belakang bus beserta sorotnya di aspal. Semua hanya mengubah `emissiveIntensity` dan warna cahaya, jadi shader tidak dikompilasi ulang.
- **Ritme keramaian harian** (`keramaianTerminal` di `src/sim/waktu.ts`, kurva di `RITME` `src/config/waktu.config.ts`): jam sibuk pagi (±06–09) dan sore (±16–19), sepi dini hari, sedang di siang hari. Per hari: Senin pagi (arus balik), Jumat sore & Minggu sore lebih ramai, Sabtu siang agak ramai, Minggu pagi lengang. HUD menampilkan pil **Jam sibuk / Ramai / Sedang / Sepi** di bawah jam. Ritme mengatur **permintaan**: di adegan (`terapkanRitme` di `src/game/laju.ts`) bus datang lebih jarang dan lebih kosong saat sepi sehingga calon penumpang juga lebih sedikit; di ekonomi versi yang dilandaikan (`EKONOMI.tycoon.pasar.ritmeMin`) menurunkan arus & pendapatan di jam sepi (lihat Pasar penumpang). Kapasitas tiap area tidak berubah, jadi antrean menumpuk di bottleneck saat jam sibuk lalu surut saat sepi, dan bus malam tetap bisa berangkat penuh mengangkut sisa penumpang (kursinya tetap). Pengunjung yang duduk di aula, yang makan, dan anak di taman berkurang saat sepi (sebagian tetap menunggu bus subuh), begitu juga lalu lintas & pejalan kaki di luar (berganti hanya saat membungkus di ujung jalan, di luar layar).
- **Cuaca** (`src/sim/cuaca.ts`, angka di `src/config/cuaca.config.ts`): tiap pekan Senin–Minggu diacak **1–3 hari hujan** (bobot 30/45/25 %), masing-masing sekali di **pagi** (05–09, gerimis sampai sedang), **siang** (11.30–15.30, paling deras, sering berpetir), atau **malam** (18.30–21.30), dan selalu reda sebelum ganti hari. Acakannya memakai benih cuaca (`benihCuaca`) yang dibuat sekali saat game baru dan ikut disimpan di save: jadwal hujan berbeda di tiap game, tapi tidak berubah saat game ditutup lalu dibuka lagi (save lama otomatis diberi benih saat dimuat). Hari pertama tidak memilih hujan pagi yang sudah lewat sebelum game dimulai. Langit mendung dulu ±1 jam sebelum hujan. Efeknya (`src/game/hujan3d.ts`, `terapkanCuaca` di `langit.ts`): langit & kabut kelabu, matahari meredup sehingga bayangan melunak, lampu ikut menyala sebagian; butiran hujan miring tertiup angin (digerakkan di vertex shader) yang berhenti di atap kaca terminal; cipratan cincin di aspal & paving; tanah, marka, rumput, dan genteng menggelap basah lalu mengering perlahan (±2 jam terminal) dengan genangan mengilap; lampu bus menyala; pejalan kaki di trotoar berkurang; orang di luar atap membuka payung warna-warni (±15 % menerobos tanpa payung, anak berlindung di payung orang tuanya), pengunjung di luar berteduh, petugas di luar berjaga berpayung. Saat hujan deras, kilat petir sesekali menerangi langit disusul guntur. HUD menampilkan ikon awan hujan.

## Tampilan layar (portrait & landscape)

Overlay DOM dirancang dalam piksel logis lalu di-scale supaya selalu **mengisi layar penuh** tanpa pita kosong (`src/ui/bingkai.ts`):

- **Portrait**: lebar logis 720, tinggi mengikuti layar. HUD ringkas di atas (kas, laba hari ini, arus, pil tipe terminal & kepuasan; jam, hari, keramaian), adegan 3D di tengah, panel tab pengelolaan di bawah.
- **Landscape**: tinggi logis 720, lebar mengikuti layar. Adegan 3D di kiri, bilah samping kanan berisi HUD lalu panel tab pengelolaan.
- Skala dibatasi 1,1× supaya teks tidak membesar berlebihan di monitor lebar; sisa ruang dipakai tata letak (CSS flex di `src/ui/gaya.css`, kelas `#ui.potret` / `#ui.lanskap`). Wadah canvas 3D ditempatkan tepat di atas kotak `.area-adegan`, jadi selalu pas walau tinggi HUD/panel berubah (mis. baris petunjuk muncul).
- Tema gelap menyatu untuk HUD, kartu & baris tiap tab (aksen warna per area, sorotan merah berdenyut untuk area paling lambat di kartu kapasitas), dan popup. Tombol suara & kamera melayang di pojok kanan atas adegan.
- **Panel ringkas**: tombol "Ringkas" menyembunyikan tab & isinya supaya adegan lebih leluasa. HUD ikut diringkas: kas, laba singkat, jam, dan kecepatan. Di landscape bilah samping menyempit dari 400 ke 152. Tombol buka panel hanya panah (titik merah bila ada hadiah untuk diklaim). Popup offline ditutup dengan "Ambil", mengetuk area gelap di luarnya, atau Esc. Pilihannya disimpan (`terminal-bus-tycoon/panel`).
- **Panel layar penuh**: tombol di ujung kanan bilah tab membuat panel menutupi adegan supaya pengaturan yang banyak lebih leluasa. Portrait: HUD tetap di atas dan panel mengisi sisa layar; landscape: bilah melebar dengan isi di tengah (paling lebar 920 px logis). Selama itu adegan 3D tidak digambar (hemat baterai; ekonomi tetap berjalan) dan kanvasnya dibiarkan di tempat (`bingkai.ts`), jadi sudut kamera tetap saat panel dikecilkan lagi lewat tombol yang sama atau Esc. Tidak disimpan: game selalu mulai dengan adegan terlihat.
- **Label area di peta** (`src/game/zona3d.ts`): nama area (Peron, Loket, Keberangkatan) berpanah "›"; area yang membatasi arus jam sibuk lantainya disorot merah berdenyut (tanpa label teks). Label Pangkalan bus hanya muncul saat pangkalan yang paling lambat. **Mengetuk label** membuka tab Bangun di bagian area itu (Peron & Keberangkatan → jalur bus, Loket → jendela loket, Pangkalan → petak bus; panel ringkas dibuka dulu) dan barisnya berpendar sebentar. Lapisan label tidak menerima pointer, jadi geser kamera tetap jalan: ketukan di kanvas dicocokkan dengan kotak label terakhir (`areaDiKetuk`, kelonggaran 10 px), lebih dulu daripada bus telolet.
- Saat layar diputar, kamera dibingkai ulang: landscape memuat seluruh terminal, portrait memuat inti terminal (pangkalan, gedung, ruang tunggu; peron kedatangan tinggal digeser).

## Tampilan 3D (three.js)

Terminal dirender sebagai adegan 3D dengan kesan foto maket: kamera perspektif sempit dengan elevasi 42° (sudut hampir isometrik), matahari dengan bayangan lembut, cahaya langit, pantulan langit di kaca dan bodi bus, serta post-processing (ambient occlusion N8AO, bloom, tilt-shift, tone mapping ACES, vignette, SMAA).

- **Kamera:** geser dengan drag. Zoom dengan cubit dua jari (HP) atau roda mouse (desktop), mengarah ke titik yang ditunjuk. Zoom bisa cukup dekat untuk melihat orang dan bus. Tampilan awal otomatis memuat seluruh inti terminal. Tilt-shift melemah saat kamera mendekat.
- **Putar kamera:** di HP, pelintir dua jari (peta berputar mengikuti jari; pelintiran di bawah 9° diabaikan supaya cubit zoom tidak ikut memutar, `src/game/kamera.ts`). Di desktop, klik kanan (atau Shift/Ctrl + klik kiri) lalu seret untuk memutar sekaligus memiringkan; tombol Q/E memutar 45°. Tombol di pojok kanan atas area adegan: putar kiri/kanan 45° (beranimasi) dan kompas yang jarum merahnya selalu menunjuk utara; ketuk kompas untuk kembali ke arah & kemiringan awal. Kemiringan dibatasi 25°–75° dari tanah.
- **Denah** (`src/game/tata-letak.ts`, 1 unit = 1 petak ≈ 5 m):
  - jalan raya bermedian dengan gapura masuk/keluar dan pos retribusi (muncul setelah dibangun)
  - jalan dalam satu arah (lajur halte + lajur sirkulasi); di kedua ujungnya jalur belok beraspal berkerb melewati bukaan median (masuk di barat, keluar di timur), jadi bus tidak melintas di atas paving/rumput
  - peron kedatangan berkanopi kaca lengkung dengan **5 halte** (berjarak 3,6 petak) di ujung barat, taman kota di belakangnya. Halte keberangkatan berjarak 4 petak. Celah antarbus yang berhenti cukup untuk bus belakang berbelok keluar ke lajur sirkulasi tanpa menyenggol bus di depannya (dites, sisa ruang ≥ 0,35)
  - pangkalan bus parkir serong berisi **20 petak** (jarak 1,25; tes memastikan bus yang parkir, masuk, dan keluar petak tidak menyenggol bus di petak sebelahnya), **dikelompokkan per jurusan** keberangkatan: empat kelompok × 5 petak (`KELOMPOK_PARKIR` di `tata-letak.ts`: JAKARTA · BANDUNG, SEMARANG · YOGYAKARTA, SOLO · MALANG, SURABAYA · DENPASAR), masing-masing diawali **pulau taman bertiang papan jurusan** di tengah pangkalan (menempati satu posisi petak, jadi bus yang keluar-masuk petak sebelahnya tidak menyenggolnya; dites) dengan papan bersilang serong empat muka yang menjulang di atas atap bus, sehingga terbaca dari arah kamera mana pun dan tidak tertutup gedung, plus tanda lantai sewarna di tiap petak. Pangkalan sekaligus **tempat cuci bus**: saluran air di tiap petak dan pos cuci (papan "CUCI BUS", tandon air, gulungan selang, lampu sorot) di ujung timur
  - **terminal terpadu** (`src/game/gedung3d.ts`): gedung utama berupa aula kaca yang isinya terlihat dari kamera. Atapnya lengkung kaca berusuk baja putih dengan tritisan logam, fasadnya tirai kaca bening. Di depannya ada selasar bertiang, gapura "TERMINAL TERPADU", bordes landai di pintu masuk, dan atrium kaca berjam di atas pintu
  - **aula loket** di dalam gedung utama: delapan jendela loket tiket di dinding utara (meja berwarna tahap loket, kaca loket, petugas di baliknya, papan nomor & nama PO pemilik jendela, papan "LOKET TIKET BUS"), labirin antrean di depannya (tali sabuk bertiang keliling dan di antara lajur, celah belokan bergantian di barat dan timur, dua baris per lajur), minimarket, apotek, ATM center, dua pintu di dinding barat ke sayap barat (bagian bawah dinding masif, di atasnya kaca supaya isi sayap barat terlihat), deretan kursi, meja informasi, papan jadwal besar, dan penunjuk arah ke ruang tunggu. Dinding dalam tidak membuang bayangan supaya deretan loket tetap terang
  - **sayap barat** (`src/game/sayap3d.ts`, denah & titik singgah di `tata-letak.ts`): bangunan beratap kaca yang menempel dinding barat aula di tepi taman. Isinya lorong di sepanjang dinding aula, **toilet pria** (bilik berpintu biru, urinoir, wastafel berkaca), **toilet wanita** (bilik berpintu merah muda, wastafel), serta **tempat wudhu** (keran berderet, saluran air) dan **musholla** untuk pria dan wanita (karpet hijau, sajadah per shaf menghadap kiblat di barat, mihrab, rak alas kaki). Sekat antarruangan rendah dan fasad selatannya kaca, supaya isinya terlihat dari kamera. Papan "TOILET" & "MUSHOLLA" di atas pintunya di aula.
  - **ruang tunggu keberangkatan** yang menyatu dengan ujung timur gedung utama: aula berdinding & beratap kaca (rusuk baja putih), empat blok kursi (masing-masing 60 kursi; terpasang sebanyak unit kursi yang dibangun, mulai dari blok terdekat gerbang Jalur 1), kios, meja makan, papan jadwal digital, dan **lima gerbang** "JALUR 1–5" yang langsung membuka ke peron keberangkatan (5 halte), tepat di depan pintu bus di tiap halte
  - plaza dengan air mancur, taman, dan parkir mobil & motor (baris mobil pertama beserta deret motor terisi setelah lahan parkir pertama dibangun, baris kedua setelah lahan parkir kedua)
- **Sekitar terminal** (`src/game/sekitar3d.ts`, `src/game/lingkungan3d.ts`): kota berlapis dengan masjid, jalan lingkungan dua arah dengan lalu lintas mobil/angkot/motor (`src/game/lalu-lintas.ts`), deretan ruko berpapan nama, kampung beratap genteng, SPBU, tiang listrik berkabel, dan pejalan kaki di trotoar.
- **Keramaian** (`src/game/dunia-visual.ts`) adalah model *dekoratif*, bukan simulasi ekonomi. Siklus bus: masuk → turunkan penumpang → parkir serong & dicuci → ngetem di halte keberangkatan → keluar. **Cuci bus**: bus tiba berdebu (badannya kusam). Di petak parkir, kenek turun dari pintu depan dan mengelilingi bus sambil menyabun (gumpalan busa muncul mengikuti langkahnya); sopir (kemeja putih, bertopi) turun menyusul dan mengelilingi bus sambil membilas (semprotan air, busa luntur, debu hilang), lalu keduanya naik lagi. Petak lalu basah dan mengering perlahan (`src/game/cuci3d.ts`). Bus baru boleh berangkat setelah bersih, lalu menunggu jadwal jurusannya selama `ISTIRAHAT_DETIK` (45 detik, sopir & kenek istirahat), jadi pangkalan biasanya berisi ±8–10 bus dan bisa penuh 20 bus bila keberangkatan lambat. **Peron kedatangan**: semua bus yang berhenti di samping peron menurunkan penumpang bersamaan (bergiliran; laju turun total tetap laju area peron, jadi peron yang lambat tetap terlihat sebagai bottleneck), dan bus tidak bergerak selama penumpangnya turun. Isi bus yang datang bervariasi ±30 %, jadi bus yang lebih kosong selesai lebih dulu: ia langsung berangkat, dan bila bus di depannya masih menurunkan penumpang ia mendahului lewat lajur sirkulasi. Bus yang baru datang langsung mengisi halte kosong **terdepan**. Bila bus di belakang halte itu masih menurunkan penumpang, bus baru masuk ke lajur sirkulasi, menyalipnya, lalu berbelok masuk tepat di depannya (`ruteKeHalteDatang`, dites bebas senggolan walau semua halte lain terisi). Bus baru menunggu di jalan raya hanya bila kelima halte terisi. Di halte keberangkatan, bus belakang yang sudah penuh (atau habis waktu ngetem) mendahului bus yang masih memuat di depannya. Saat berbelok, bus hanya memperhitungkan bus di lajur tujuannya (`ruangDepan` di `dunia-visual.ts`). Bus yang selesai menurunkan penumpang ditugaskan ke jurusan yang kelompok petaknya paling lowong (seri diundi, supaya semua kelompok terisi), parkir di salah satu petak kosong kelompok itu, dan pengumuman keberangkatannya menyebut jurusan tersebut. Lama cuci `CUCI.detik` (21 detik: tiap petugas berjalan dengan laju jalan biasa) ada di `tata-letak.ts`; karena pangkalan biasanya berisi beberapa bus, cuci tidak menurunkan arus keberangkatan. Penumpang mengalir dalam dua arus terpisah. **Penumpang turun** berjalan dari peron kedatangan lewat jalur pejalan kaki di sisi barat gedung, keluar lewat gerbang "PINTU KELUAR" di pagar belakang, lalu lewat gang di sela ruko ke trotoar jalan belakang (pulang). Mereka tidak pernah antre lagi. **Calon penumpang** datang dari luar, yaitu dari trotoar jalan belakang lewat gerbang "PINTU MASUK" atau, bila sudah ada lahan parkir, dari parkir mobil. Mereka memilih baris yang lebih pendek, masuk lewat pintu gedung dan celah tali di pojok labirin, lalu **menyusuri lajur labirin yang berkelok** (lintasan `JALUR_ANTREAN` di `tata-letak.ts`) sampai ujung barisnya, sama seperti yang sudah antre. Tidak ada yang memotong antarlajur, dan pejalan di baris yang sama menjaga jarak satu slot supaya tidak berhimpit. Urutan antrean baru diambil saat tiba, jadi yang masih berjalan tidak dihitung antre dan labirin hanya penuh kalau loket memang lambat. Yang sudah antre maju menyusuri lajur yang sama (dua baris berdampingan) tanpa menembus tali. Bila labirin penuh, antrean meluap keluar pintu dan berbaris di depan fasad. Kepala antrean dipanggil ke jendela loket yang paling sepi dengan laju loket. Urutan antre didahulukan, tapi bila orang terdepan satu baris masih melangkah maju, orang terdepan baris sebelahnya yang sudah siap dipanggil duluan (`kepalaSiap`), seperti antrean dua baris sungguhan; tanpa ini, orang yang tiba bergerombol per baris membuat satu baris menunggu baris lain maju selangkah demi selangkah dan antrean menumpuk di loket yang sebenarnya longgar (paling banyak 5 pembeli per jendela: satu bertransaksi, dua menunggu di belakangnya, dua di kiri-kanan saat ramai). **Transaksi di jendela tidak instan**: petugas santai selama arus calon penumpang mengizinkan (±2,5–7 detik, bervariasi per pembeli), lalu bergegas saat antrean mulai menumpuk (mis. dua bus menurunkan penumpang sekaligus) sampai sanggup mengikuti laju loket penuh, jadi deretan jendela tidak menjadi hambatan palsu. Supaya transaksi bisa sepanjang itu, arus visual dibatasi ±0,24 orang/detik per jendela yang buka (`batasArusJurusan` di `laju.ts`): terminal dengan sedikit jurusan tampak lebih sepi dan makin ramai tiap jurusan baru dibuka. **Mampir**: ±1/3 pembeli yang bepergian sendiri mampir dulu setelah membeli tiket: ke toilet (bilik atau urinoir, lalu wastafel; pria & wanita ke ruangnya masing-masing, dilihat dari jilbab), ke musholla (wudhu lalu sholat: berdiri dan duduk bergantian menghadap kiblat; jauh lebih ramai ±50 menit setelah awal waktu sholat), ke ATM center, atau ke minimarket/apotek yang sedang buka (setelah kios atau toko dibangun). Penumpang yang sudah duduk sesekali bangun ke kios ruang tunggu (kopi, roti, oleh-oleh) lalu kembali ke kursinya. Tiap bilik, keran, sajadah, mesin ATM, dan tempat berdiri di toko/kios dipakai satu orang; kursinya tetap dipesan dan ia baru bisa dipanggil ke bus setelah duduk lagi. Setelah membeli tiket, mereka berjalan menyusuri aula ke pintu ruang tunggu, lalu duduk di kursi (kursi dipilih menyebar, baris depan lebih disukai). Saat loket berhenti, jendela kosong dan antrean tertahan. Penumpang dipanggil sejak busnya keluar pangkalan, berdiri dan berkumpul di balik gerbang. Setelah bus berhenti, mereka keluar gerbang dan naik lewat pintu depan. Bus menunggu sampai penumpang yang sudah dipanggil naik semua. **Bus di halte keberangkatan tidak pernah maju** ke halte depan yang kosong (penumpang tidak bingung pindah gerbang); sebaliknya bus dari pangkalan langsung mengisi halte kosong mana pun (terdepan dulu): halte paling belakang lewat lajur halte, halte lain lewat lajur sirkulasi lalu berbelok masuk, walau halte di belakangnya terisi (`ruteKeHalteBerangkat`, dites bebas dari bus di semua halte lain). Jumlah calon penumpang yang datang mengikuti jumlah penumpang yang turun, dan loket berjalan relatif terhadap arus nyata itu. Karena itu kerumunan tetap menumpuk tepat di depan area yang paling lambat, walau jumlah bus dibatasi manuvernya. Muatan per bus naik seiring throughput (12–20 penumpang). **Rombongan** (`src/game/rombongan.ts`): ±20 % penumpang bepergian bersama anak atau pendamping dewasa. Anggota rombongan bukan agen tersendiri (tidak memakai slot antrean atau jendela loket): ia menapak jejak pemimpinnya sedikit di belakang-samping seperti bergandengan tangan, sehingga tidak menembus tali labirin. Di ruang tunggu mereka duduk berdampingan di kursi sebelah yang dipesankan saat membeli tiket, dan kursinya dilepas saat naik bus. Semua gerak maju dengan kurva halus, dan bus menjaga jarak dengan bus di depannya. Lajunya diturunkan dari state sim (`src/game/laju.ts`): area paling lambat berjalan paling pelan, sehingga **antrean orang menumpuk tepat di depan bottleneck**. **Laju jalan alami**: semua orang berjalan `KECEPATAN_JALAN` = 0,45 petak/detik (sama dengan pejalan kaki di trotoar, ±12% per orang, ±2,6 langkah/detik). Karena itu tiap orang lebih lama di layar dan kerumunan lebih ramai (batas `MAKS_ORANG` 480), sedangkan arus visual dibatasi `LAJU_MAKS` 1,8 orang/detik di `laju.ts` supaya tetap di bawah daya tampung jalan kaki (antrean dua baris, jendela loket, gerbang) dan tidak muncul hambatan palsu. Arus visual ini sudah lama berupa gambaran (dikompres logaritmik dari angka HUD); ekonomi tidak berubah.
- **Loader kemajuan bus** (`src/game/label-bus.ts`, murni dan dites; digambar `src/game/label-bus3d.ts`): di **peron kedatangan**, bus yang menurunkan penumpang berlabel "TURUN 7/16" (penumpang turun / penumpang yang dibawa, `muatanDatang`) dengan bilah berwarna tahap peron. Di **petak parkir jurusan**, bus yang sedang dicuci berlabel cincin loader berwarna jurusannya dengan ikon tetes air, yang berubah jadi centang hijau saat bersih. Bentuknya ringkas karena petak parkir berdempetan. Di **jendela loket**, pembeli yang sedang membeli tiket mendapat cincin loader berwarna tahap loket dengan ikon tiket (kemajuan dari `lamaTimer` transaksi, `src/game/label-loket.ts`); centang singkat saat tiket selesai dibeli, lalu cincin berikutnya mulai untuk pembeli berikutnya. Cincin loket disembunyikan bila kamera terlalu jauh sehingga cincin jendela bersebelahan bertumpuk. Semua loader memudar sebentar setelah selesai. **Label keberangkatan**: saat bus mulai memuat di halte keberangkatan, di atasnya muncul label jurusan dan **penumpang naik / kapasitas bus** (mis. "SURABAYA 12/19") dengan bilah kemajuan: bagian penuh = sudah masuk pintu, bagian samar = sudah dipanggil dan sedang berjalan ke bus. Label hijau saat penuh, bertahan sebentar setelah bus berangkat, dan mengecil saat kamera menjauh supaya label di halte bersebelahan tidak saling menutupi.
- **Efek "+Rp"** (`src/game/kas-visual.ts`, murni dan dites; digambar `src/game/pop-uang3d.ts`): pendapatan menurut sim tampil di tempat transaksi yang paling dekat: di atas **jendela loket** saat tiket terjual (biaya layanan & sewa jendela, ikon koin persen: bagian terminal, bukan harga tiket), di atas **bus yang baru parkir** di petak (retribusi, ikon bus), di **lorong parkir** saat calon penumpang turun dari kendaraan pengantar (parkir, ikon P), dan di **kios/toko** saat penumpang selesai belanja (sewa kios & toko serta toilet, ungu). Keramaian hanya wakil arus penumpang sim, jadi besar tiap "+Rp" = pendapatan per detik sumber itu ÷ rata-rata transaksi yang terlihat per detik, ditambah koreksi kecil dari selisih yang terkumpul: angkanya stabil, ikut membesar seiring terminal berkembang, dan totalnya sama dengan pendapatan yang masuk. Angka yang tampil dibulatkan ke dua angka penting (`bulatkanPop`) dan baru berganti bila sasarannya bergeser lebih dari 12 %, jadi "+Rp" berturut-turut sama besar; selisih pembulatan terbawa ke "+Rp" berikutnya. Karena tiap orang di keramaian mewakili beberapa penumpang sim, "+Rp" di loket bukan harga satu tiket (harga tiket di kartu PO; biaya layanan per penumpang di baris tarif tab Terminal). Lompatan waktu (muat save, tab tertidur) tidak dibagikan karena sudah masuk laporan offline. Efek naik lalu memudar (±1,5 detik), mengecil saat kamera menjauh, dan tidak naik bila pemain memilih kurangi gerak.
- **Klakson telolet** (`src/game/telolet.ts`, murni dan dites; spanduk `src/game/telolet3d.ts`): ketuk bus mana pun (di jalan, halte, atau pangkalan) untuk membunyikan klakson telolet; label "♪ TELOLET!" muncul dan ikut bergerak bersama busnya. Ketukan dibedakan dari geser/zoom kamera (bergeser < 8 px, < 0,4 detik); bus yang sama baru bisa berbunyi lagi setelah 1,6 detik. Pukul 07.00–17.30 (tidak saat hujan) tiga anak berdiri di trotoar seberang jalan raya, dua mengangkat spanduk kardus "OM TELOLET OM"; mereka melambai ke tiap bus yang lewat di depannya, dan melompat kegirangan sambil melambai ±3 detik saat telolet berbunyi dalam jarak 26 petak.
- **Livery mitra PO** (`src/config/livery.config.ts` warna/pola/tulisan, `src/game/livery.ts` murni dan dites, digambar `src/game/kendaraan3d.ts`): dibuat dari gambar samping atlas (varian 1 = `bus/oranye-1`, varian 2 = `bus/kuning-2`) yang piksel cat badannya dikenali lewat rona lalu diwarnai ulang ke warna PO dengan bayangan & sorotan dipertahankan; pola aksen (garis di atas jendela, dua warna di badan bawah, atau sapuan miring) hanya mengenai cat badan, dan nama PO ditulis besar di pita atas kedua sisi (dipotong ke cat badan, jadi terputus di pintu seperti stiker) serta di papan tujuan depan. Bus terminal yang baru muncul memakai livery PO pemiliknya (lihat Jurusan di adegan) dan tetap memakai livery itu sampai pergi; bus yang lewat di jalan raya memakai livery bawaan atau livery PO terdaftar (tiap PO berbobot 2).
- **Tanda kelas terminal** (`src/game/kelas3d.ts`): papan nama balok gapura berganti TERMINAL TIPE C (abu-abu) → TIPE B (biru) → TIPE A (gelap bertulisan emas) → TERMINAL TERPADU (cokelat emas), atau "TERMINAL <NAMA>" dengan tipe di baris kedua bila pemain menamai terminalnya (papan dibuat ulang hanya saat nama/kelas berubah); mulai Tipe B umbul-umbul warna-warni berkain bergelombang berdiri di sepanjang median jalan raya (tidak di bukaan & tiang lampu), mulai Tipe A lampu hias melendut di antaranya dan menyala di malam hari, dan kelas Terpadu mendapat bintang emas di atas gapura (satu per bintang, maks. 5).
- **Foto terminal** (`src/ui/foto.ts`, tombol kamera di kolom kontrol, web saja): memotret adegan 3D tanpa label & tombol (render sekali lalu disalin sebelum kanvas WebGL dibersihkan), menambahkan bingkai bawah berisi ikon & nama game, keterangan terminal pemain (jurusan, penumpang/detik, mitra PO), dan "Main gratis di bustation.games", lalu menawarkan **Bagikan** (Web Share API dengan berkas, umumnya di HP) atau **Simpan gambar** (unduh JPEG). Atur kamera dulu untuk memilih sudut. Analitik: `foto_terminal`, `share` (method `web_share`/`unduh`). Belum untuk APK (WebView Android tidak punya Web Share).
- **Mode sinema** (video promosi; tombol papan klapper di kolom kontrol, `src/ui/sinema.ts`; kamera `src/game/sinema.ts` murni dan dites): popup memilih kecepatan waktu (1 hari ≈ 1 menit, ≈ 3 menit, atau asli) dan cuaca (sesuai jadwal, cerah, hujan), lalu semua tampilan & label disembunyikan dan adegan memenuhi layar (9:16 di HP), kamera berputar pelan mengelilingi titik pandang saat itu (satu putaran 150 detik, zoom ±10 %, miring & geser sepanjang terminal "bernapas", mulai tanpa lompatan), dan hanya ada tanda kecil "bustation.games · jam" di pojok. Rekam dengan perekam layar HP untuk TikTok/Reels. Hanya tampilan yang dipercepat (`OpsiSinema` di `src/game/terminal3d.ts`: jam tampilan = jam main + selisih, kerumunan 2–4×); ekonomi di state tetap berjalan dengan kecepatan game biasa, jadi mode ini tidak bisa dipakai untuk mempercepat penghasilan. Ketuk layar atau Esc untuk keluar: kamera & jam kembali seperti semula.
- **Bus** (`src/game/kendaraan3d.ts`): badan satu `InstancedMesh` dengan atap melengkung dan spion. Kaca mengilap dan cat doff lewat peta kekasaran yang dibuat otomatis dari tekstur. Roda 3D berputar sesuai jarak tempuh. Pintu depan berengsel terbuka saat bus menurunkan atau menaikkan penumpang di halte. Pintu bagasi di antara roda (sisi peron, `BAGASI` di `tata-letak.ts`) diangkat selama bus di halte, dengan koper, kardus, dan tas di sampingnya dan kenek berjaga (kenek yang sama nanti mencuci bus). Posisi pintu (`PINTU_BUS` di `tata-letak.ts`) sama dengan titik naik/turun penumpang di `DuniaVisual`. Lampu rem menyala saat melambat atau berhenti, lampu sein berkedip saat berbelok, dan badan bus sedikit menunduk saat mengerem.
- **Orang** (`src/game/orang3d.ts`): orang 3D low-poly, sepuluh `InstancedMesh` untuk seluruh kerumunan. Mereka menghadap arah jalan, kaki dan lengan berayun sesuai jarak tempuh, dan penampilannya beragam (kulit, baju, celana, rambut, jilbab dan gamis, ransel, topi, tinggi badan, anak-anak). Sebagian menarik **koper beroda** (miring saat ditarik, tegak di samping saat berhenti atau duduk); saat hujan di luar atap, payung terbuka di atas kepala. Penumpang di ruang tunggu duduk menghadap gerbang; bila kursi di blok yang terpasang penuh, penumpang berikutnya berdiri menunggu di lantai blok yang belum dipasang (tanda kursi kurang). Satpam, polisi, petugas peron & gerbang, penjual kios, pengunjung yang makan, orang duduk di bangku, dan anak di taman adalah orang statis. Mesin tiket, papan jadwal, mobil golf, dan anjing juga dibuat 3D.
- **Ambient occlusion**: di tingkat kualitas tertinggi dipakai N8AO (`n8ao`), yaitu kontak bayangan di sudut dinding, kolong bus, dan celah antar-rumah. N8AO memakan 7–10 ms per frame di Intel Iris Xe, jadi tingkat lain memakai bayangan kontak yang dipanggang di bawah gedung, rumah, dan mobil (`bayanganKontak` di `src/game/geometri.ts`), ditambah bayangan kolong di bawah kendaraan yang bergerak.
- **Material**: tekstur prosedural Canvas 2D (`src/game/tekstur3d.ts`) untuk rumput, aspal, paving, genteng, bata, plester, fasad kota, atap logam, dinding tirai kaca, lantai granit, dan papan jadwal. Atap & dinding kaca ruang tunggu memakai material transparan supaya isinya terlihat dari kamera. Variasi warna skala besar per posisi dunia mencegah pola tekstur yang berulang. Semua papan nama berbagi atlas teks 2048²; papan bertulisan & bergaya sama memakai tempat yang sama, dan bila atlas penuh halaman baru dibuat otomatis (tidak menggagalkan pemuatan adegan).
- **Bayangan mengikuti kamera** (`src/game/bayangan.ts`, murni dan dites): peta bayangan matahari dipasang di atas tanah yang sedang terlihat, bukan di satu area tetap. Pojok-pojok layar diproyeksikan ke tanah, lalu dibungkus persegi di bidang tegak lurus arah cahaya (setengah sisi 12–64 unit, dibulatkan per 4 unit). Makin dekat kamera, bayangan makin tajam, dan seluruh peta termasuk peron kedatangan & taman kini ikut berbayangan. Pusatnya digeser per texel supaya tepi bayangan tidak berkilau saat kamera digeser. Normal bias mengikuti ukuran texel. Di HP, peta bayangan digambar ulang tiap 2–3 frame, tapi tetap langsung saat kamera atau matahari bergeser.
- **Langit & pantulan** (`src/game/langit3d.ts`): langit prosedural (gradasi zenit → cakrawala, pendar & piringan matahari, bulan, awan yang menebal saat mendung, pendar lampu kota di cakrawala malam) dirender ke cube map 128 px dan dipakai sebagai environment map. Kaca, bodi bus, fasad kota, dan genangan memantulkan langit sesuai jam dan cuaca: biru di siang hari, jingga saat senja, kelabu saat hujan, gelap kekuningan di malam hari. Matahari yang terpantul di kaca atap tampak sebagai kilau. Cube map hanya dibuat ulang bila langit berubah cukup jelas (paling cepat tiap 1,2 detik), ke tekstur yang sama, jadi material tidak berganti shader. Kekuatan pantulan tetap mengikuti `intensitasLingkungan` suasana, dibagi perkiraan kecerahan langit, jadi langit malam yang hampir hitam tidak membuat bangunan gelap gulita. Warna zenit (`warnaZenit`), benda langit, mendung, dan kilat ada di `Suasana` (`langit.ts`).
- **Bloom**: lampu jalan, jendela kota, papan menyala, lampu depan/rem/sein bus (warna HDR di atas putih), dan kilau matahari di kaca berpendar. Ambang bloom turun dan kekuatannya naik di malam hari. Di siang hari hanya kilau terkuat yang berpendar; kilat petir memperkuatnya sesaat.
- **Kaca & kanopi transparan dua sisi** memakai `forceSinglePass`. Tanpa itu three.js menggambarnya dua kali dan mengevaluasi ulang program shader tiap frame, salah satu beban CPU terbesar sebelum diperbaiki.
- **Kualitas adaptif** (`src/game/adegan.ts`): kalau frame lambat, kualitas turun bertahap, mulai dari rasio piksel, lalu AO, multisampling, ukuran & frekuensi peta bayangan, bloom, dan tilt-shift. Tingkat tanpa multisampling memakai SMAA (pass terpisah setelah tone mapping). Tingkat terendah tanpa bayangan dan tanpa post-processing. Shader dikompilasi sebelum frame pertama supaya tidak tersendat. Di mode dev, jumlah draw call dan segitiga dicatat ke console, dan `?tingkat=0..4` di URL mengunci tingkat kualitas untuk mengukur performa.
- Adegan 3D dimuat terpisah (dynamic import). UI dan simulasi sudah berjalan sebelum grafis siap. Kalau WebGL2 tidak tersedia, muncul pesan dan game tetap bisa dimainkan lewat panel.

## Suara

Semua bunyi disintesis dengan Web Audio (derau + osilator), tanpa file audio, jadi APK tidak membesar.

- **Lapisan latar** (kekerasan diatur tiap frame): riuh orang (celoteh dari derau berformant), mesin diesel bus yang langsam/melaju (mesin dimatikan saat parkir dicuci), gemuruh lalu lintas, semprotan air cuci, jangkrik di malam yang sepi, dan hujan.
- **Bunyi sesaat**: desis rem angin saat bus berhenti, deru mesin saat bus berangkat (kadang disertai klakson "tin-tin"), klakson kendaraan di jalan, guntur yang menyusul kilat, dan **klakson telolet** saat pemain mengetuk bus (empat melodi terompet angin, tiap bus selalu memakai melodi yang sama).
- **Pengumuman**: bel "ting-tung" (empat nada, bergema seperti di aula) lalu kalimat bahasa Indonesia, misalnya "Perhatian. Bus jurusan Surabaya sudah siap di jalur 2. Penumpang dipersilakan naik." Nomor jalur sama dengan papan "JALUR" di gerbang. Sesekali ada pengumuman kedatangan dan pengumuman umum (jaga barang bawaan, dilarang merokok, waspada calo). Jaraknya minimal 35 detik. Kalimat diucapkan dengan `speechSynthesis` bila perangkat punya suara bahasa Indonesia (mis. Chrome desktop, "Google Bahasa Indonesia"); kalau tidak (sebagian WebView Android), hanya bel.
- **Seperti dari kamera**: sumber di dekat titik pandang lebih keras, yang jauh samar, zoom masuk mendekatkan suara, dan bunyi sesaat diposisikan kiri–kanan (stereo) sesuai letaknya di layar.
- Tombol speaker di pojok kanan atas area adegan menyalakan/mematikan suara; pilihannya disimpan (`terminal-bus-tycoon/suara`). Aturan autoplay browser/WebView: suara baru mulai setelah sentuhan pertama. Suara berhenti saat app di-pause.
- Logika murni (kekerasan tiap lapisan, kejadian, teks pengumuman) ada di `src/game/suara.ts` dan dites; mesin Web Audio di `src/platform/suara.ts` (volume tiap lapisan di `MAKS_LAPISAN`).

## Aset grafis

Sumbernya satu lembar `assets/master.jpg`. Untuk memotongnya menjadi aset terpisah dan menyusun atlas game:

```bash
npm run aset
```

Keluarannya:

- `assets/potongan/<kategori>/<nama>.png`: semua potongan (bus, gedung, prop, orang, kendaraan, UI), latar dan bayangan petak sudah dihapus.
- `public/aset/atlas.png` + `atlas.json`: atlas untuk game (sekarang 512×512). Ukurannya pangkat dua supaya mipmap aktif dan tekstur tetap halus saat di-zoom out.
- `src/game/aset-data.ts`: posisi, ukuran, titik kaki, dan warna tiap frame. File ini dibuat otomatis, jadi jangan diedit manual.

Kotak potong dan opsinya ada di `tools/aset/daftar.mjs`. Untuk menambah aset, tulis kotaknya di sana lalu jalankan ulang `npm run aset`. `tests/aset.test.ts` memeriksa atlas tetap konsisten dengan `aset-data.ts`. Latar dihapus dengan flood-fill dari tepi kotak yang tidak bisa menembus celah outline 1–2 px. Potongan persegi seperti dinding dan pintu diambil sebagai `tekstur(...)` tanpa hapus latar.

Cara pakai di game:

- **Bus**: gambar tampak samping ditempel ke sisi kanan dan kiri (dicerminkan) balok bus 3D lewat "lembar bus" (bus kota ekonomi & patas; kelas lain dilukis prosedural). Muka depan (kaca, papan trayek, lampu, pelat nomor), belakang, dan atap digambar prosedural dengan warna dari gambarnya. Bus tingkat, van, dan minibus hanya lewat di jalan raya.
- **Tidak dipakai**: modul dinding bata, etalase, dan pintu (gedung terminal terpadu kini dibuat prosedural), sprite orang, prop, dan mobil golf (diganti model 3D supaya tidak terlihat seperti kartu), bus isometrik di panel kiri (saling menumpuk dan perspektifnya berbeda), atap limas, serta elemen UI dan papan bertulisan (teks bahasa Inggris tertanam di gambar). Semuanya tetap tersedia di `assets/potongan/`. Atlas game (`public/aset/atlas.png`, 512×512) hanya berisi sisi bus.

```
tests/

```

Batas antar lapisan dijaga otomatis:

- `tsconfig.sim.json` mengecek `sim/`, `config/`, dan `app/` tanpa lib DOM.
- `tests/arsitektur.test.ts` menolak import three.js/Capacitor dari lapisan murni dan dari modul logika game (denah, keramaian), serta menolak adegan yang mengubah state.

### Save & offline

- Autosave setiap 10 detik waktu main, saat app pause (Capacitor `pause`, atau tab disembunyikan/ditutup di browser), dan setelah laba offline diterapkan.
- Format JSON dengan `schemaVersion` (3); uang dalam Rupiah biasa (`number`). Blok baru yang belum ada di save lama diisi default, dan perubahan bentuk yang tidak additive memakai `MIGRASI` di `src/sim/save.ts`.
- Save korup tidak membuat crash: error di-log, salinannya disimpan ke `terminal-bus-tycoon/save-korup`, lalu game baru dimulai.
- Offline butuh **Manajer Operasional** (tanpa manajer terminal tutup: tanpa pendapatan & biaya). Laba offline = pendapatan rata-rata sehari × 60 % (tidak pernah melebihi hasil tarif bawaan) − biaya penuh, paling lama 8 jam (`terapkanOffline` di `src/sim/state.ts`). Jam terminal berhenti selama itu, jadi dihitung dari rata-rata hari biasa. Kas tetap tidak minus: bila habis, petugas berhenti satu per satu dan biayanya ikut turun (bila Manajer Operasional ikut berhenti, terminal tutup). Proyek perluasan selalu berjalan. Jam yang dimundurkan menghasilkan 0. Popup "Selama kamu pergi…" menampilkan laba, pendapatan & biaya, dan petugas yang berhenti.
